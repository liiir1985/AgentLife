# 配置生成 Skill 设计

## 1. 文档目的

本文定义配置生成 Skill 的产品级模型、职责边界、输入输出语义、生成流程、失败结果和跨系统协作方式。

配置生成 Skill 是供 AI Agent 使用的设计时能力。它接收具有明确字段语义的结构化输入，其中字段值可以是世界观描述、人物小传、对话记录或经历描述等自然语言文本；Skill 根据字段已经确定的类型、归属和用途，将这些文本转换为结构化候选配置或初始记忆候选。

Skill 只生产候选数据，不负责持久化、用户审阅、批准、应用、角色创建或运行时状态修改。候选数据的保存、审阅和应用由独立系统负责。

## 2. 设计目标

配置生成 Skill 需要满足以下目标：

* 以结构化字段为输入边界，使每段自然语言文本具有唯一确定的产品语义。
* 支持初始配置生成和初始记忆提取两种工作模式，并严格分离两类输出。
* 从字段内自然语言提取有来源的结构化候选，不把未表达内容补成事实。
* 只使用目标规范已经注册的配置类型、引用关系、默认值和规则词汇。
* 在资料缺失或冲突时继续生成不受影响的部分，并以结构化诊断标记阻塞范围。
* 保留从候选值到输入字段及文本片段的来源链。
* 允许使用外部验证诊断改进候选，但不拥有权威验证或提交权限。
* 保持平台、模型、序列化格式、持久化技术和用户界面无关。

## 3. 职责边界

### 3.1 Skill 负责

配置生成 Skill 负责：

* 核对输入包、输入类型、字段语义版本和目标规范版本。
* 在字段允许的语义范围内理解、切分和归纳自然语言文本。
* 生成首版候选配置、确定性规则及其引用关系。
* 从合格的角色背景、经历、对话和世界内记录字段中提取初始 Long-term Memory 候选。
* 生成由候选长期记忆支持的主观实体档案断言候选。
* 记录显式输入、规范默认值、冲突、未确定内容和不适用内容之间的区别。
* 返回候选数据、来源关系、依赖关系和结构化诊断。
* 根据外部验证器返回的结构化诊断生成修订候选。

### 3.2 Skill 不负责

配置生成 Skill 不负责：

* 接收没有类型、归属和用途声明的任意纯文本或文档集合。
* 猜测某段文本属于世界事实、人物 Identity、角色经历、作者说明还是示例。
* 定义新的配置类型、规则词汇、领域扩展或运行时权限。
* 对配置或记忆执行权威验证。
* 把候选写入持久化配置存储、记忆存储或运行时状态。
* 提供用户审阅界面、差异呈现、批准流程或发布操作。
* 创建角色、世界实体、记忆实例或模拟事件。
* 修改当前有效配置、执行迁移或适配已有运行状态。
* 参与世界 Tick、Fast Forward、认知屏障或运行时规则生成。

## 4. 工作模式

### 4.1 初始配置生成模式

初始配置生成模式把带明确字段语义的世界、人物和系统设计文本转换为首版候选配置。它可以生成世界、人物、身体、感知、认知、记忆、时间调度和第三方行为树适配所需的数据及确定性规则。

该模式只面向新运行配置的首版创作。它不读取当前有效配置作为基线，不生成增量补丁，也不决定如何把候选应用到配置存储。

### 4.2 初始记忆提取模式

初始记忆提取模式把已经明确标记为角色背景经历、对话记录、世界内记录或其他合格来源的自然语言字段，转换为初始 Long-term Memory 和主观实体档案候选。

该模式不是普通配置生成的隐式副作用。调用方必须明确选择该模式并提供目标记忆所有者、来源资格、叙事视角和信息获得方式。输出与候选配置分开，后续由记忆系统的导入能力独立验证和处理。

### 4.3 共享能力与隔离

两种模式可以共享字段读取、文本片段定位、实体引用、来源追踪、诊断和结构化生成能力，但不能共享权威输出类型或提交路径。

一次请求可以同时要求两种候选产物，但结果仍必须形成两个互不嵌套的候选集合。候选配置不能携带角色私有记忆，初始记忆候选也不能修改人物 Identity 或配置定义。

## 5. 结构化输入模型

### 5.1 结构化的含义

结构化输入不要求上游先把自然语言拆成事实、规则、记忆痕迹或实体断言。结构化表示每段自然语言位于具有明确产品语义的字段中，字段定义已经确定：

* 该文本描述的领域和对象。
* 文本属于设定、Identity、经历、对话、记录、说明还是示例。
* 文本归属于哪个世界、角色、来源或设计单元。
* 文本允许生成哪些候选产物。
* 文本是否可以作为初始记忆来源。
* 文本与其他字段之间如何引用。

Skill 可以理解和切分字段内部的自然语言，但不能跨越字段语义，把作者说明解释为世界事实，或把 Identity 背景自动解释为角色记忆。

### 5.2 输入包

每个输入包至少表达：

* 输入包身份和输入语义版本。
* 请求的工作模式。
* 目标命名空间和目标规范版本。
* 具有稳定身份、类型和归属的输入对象。
* 输入对象之间的显式引用。
* 各自然语言字段的字段类型和来源定位。
* 需要调用的领域范围。

具体序列化字段和协议不在本文定义。无论采用何种格式，相同字段类型都必须具有稳定、版本化且唯一的语义。

### 5.3 文本字段

文本字段保存自然语言内容及其结构化上下文。字段上下文至少能够确定文本类型、所属对象、来源身份、允许用途和文本片段定位方式。

字段可以保存完整人物小传、地点描述、身体设计说明、规则说明或对话记录。Skill 可以在字段内划分来源片段，但不得通过文件名、章节标题、写作语气或常识猜测字段用途。

如果字段类型允许多种输出用途，输入必须显式声明本次允许的用途。未声明的用途不能由 Skill 自动开启。

### 5.4 值状态

设计输入需要区分以下状态：

* **显式内容：** 设计者已经给出的文本或结构化值。
* **请求规范默认值：** 明确要求目标配置类型使用其已注册默认值。
* **未确定：** 设计者尚未作出决定，不能生成具体值。
* **冲突候选：** 输入保留多个互不兼容的设计方向，尚未选定。
* **不适用：** 该输入对象明确不使用某项能力。

空文本、字段缺失和未确定不是请求默认值。Skill 不能把它们静默折叠为同一种情况。

### 5.5 引用与来源

输入中的对象引用必须显式指向稳定身份，不能只依赖显示名称或自然语言中的相似称呼。自然语言提及可以作为待解析线索，但在生成正式引用前必须唯一关联到输入包公开的目标。

来源定位应能够把候选追溯到输入对象、字段及字段内片段。实现可以使用位置范围、片段身份或其他稳定方式，但不能只保存改写后的摘要而丢失原始来源。

## 6. 配置生成输入

### 6.1 领域输入

配置生成模式接受已经按字段语义分类的设计输入，包括：

* 世界静态设定、初始世界状态和世界规则说明。
* 人物 Identity、能力层级、控制入口和主要实体标记设计。
* 身体模板、器官、能力、资源、指标、过程和效果映射设计。
* 感知通道、材料、筛选、显著度、分辨率和渲染设计。
* 认知需求、决定输出、意图和等待边界设计。
* 记忆类型、容量、索引、语义提供器、相关性和触发设计。
* 固定 Tick、运行模式、活动索引、屏障和保存边界设计。
* 第三方行为树组件引用、适配能力、局部视图白名单和计划输出约束。

字段分类只说明文本的产品语义，不要求上游预先把自然语言转换成最终配置项。

### 6.2 规范上下文

Skill 生成候选时必须获得目标规范上下文，包括可用配置类型、领域扩展、引用目标、默认值、组合与覆盖语义、规则词汇、权限边界和兼容要求。

规范上下文是只读能力描述，不是当前有效运行配置。Skill 不能从规范上下文取得运行状态，也不能通过生成结果扩展规范自身。

### 6.3 第三方行为树适配

系统不详细设计行为树节点语言、编辑器或行为内容。配置生成 Skill 只根据第三方组件已经公开的适配规范生成候选引用和适配配置。

生成结果仍必须满足系统约束：行为树确定性运行、不得调用 LLM、只能读取受限局部视图、只能使用有限黑板，并通过普通身体计划入口输出。第三方组件无法表达这些约束时，Skill 返回无法表达或不兼容诊断。

## 7. 初始记忆提取输入

### 7.1 来源资格

初始记忆来源字段必须明确声明为以下一种合格用途：

* 目标角色的背景经历。
* 目标角色参与或获知的对话记录。
* 目标角色接触过的世界内记录。
* 其他由输入规范明确允许形成角色初始记忆的资料。

普通人物 Identity、自我定义、作者说明、创作备注、示例文本和未声明用途的详细资料不具有记忆来源资格。

### 7.2 记忆所有者与视角

每个可提取来源必须明确目标记忆所有者。对话或多人经历还需要表达参与者、说话者、目标角色能够接触的内容，以及信息是亲历、听闻、推测还是来自外部记录。

Skill 不能因为某角色出现在文本中，就推断该角色看见、听见、理解或记住了全部内容。缺少视角或可知范围时，相应部分阻塞。

### 7.3 时间与实体关联

来源可以提供精确时间、相对时间、顺序关系或未知时间。Skill 只能保留输入支持的时间精度，不能为了排序或导入而补造精确日期或模拟 Tick。

输入可以提供实体引用和自然语言提及。只有能够唯一解析到允许目标的提及才能形成实体关联；无法唯一解析的提及保留为未决诊断，不能绑定到猜测的世界实体。

### 7.4 原始来源定位

初始记忆候选必须保留原始来源字段和字段内文本片段定位。结构化输入可以嵌入自然语言原文，也可以以受控引用提供文本；无论采用哪种方式，Skill 必须能够证明每个候选语义来自哪个合格片段。

## 8. 初始配置候选输出

### 8.1 候选包

配置候选包表达一个首版运行配置的候选内容，包括目标命名空间、目标规范版本、候选配置定义、候选规则、稳定身份、引用、依赖和来源关系。

候选包不是当前有效配置，也不具有待自动应用的隐式命令。下游系统可以保存、审阅或提交该数据，但这些行为不属于 Skill 结果语义。

### 8.2 候选值来源

每个候选值需要区分：

* 直接来自显式输入的值。
* 从字段内自然语言归纳得到且仍受原片段支持的值。
* 由输入明确请求并从目标规范取得的默认值。
* 因冲突或信息不足而未生成的值。

规范默认值必须记录默认定义来源。Skill 不能把自身常识、提示示例或历史输出标记为规范默认值。

### 8.3 分区结果

输入缺失或冲突时，Skill 应按引用和依赖关系确定影响范围。与阻塞项无依赖的配置分区可以继续生成；直接或间接依赖阻塞项的分区必须标记为未完成。

部分候选不能伪装成完整可加载配置。输出需要让下游系统明确区分已生成分区、阻塞分区和二者之间的依赖。

### 8.4 禁止输出

配置候选不能包含：

* 持久化地址、数据库操作或文件写入指令。
* 审批状态、用户授权或发布命令。
* 用户界面布局、表单和差异呈现要求。
* 绕过共享或领域验证的标记。
* 角色隐藏记忆、当前认知、意图或主观实体认识。
* 运行时才能确定的事实或状态变化。

## 9. 初始记忆候选输出

### 9.1 独立候选包

初始记忆候选必须形成独立产物，并声明目标角色、目标记忆规范版本、所依赖的候选配置身份以及来源集合。

初始记忆候选不是配置定义，也不是已经导入的记忆状态。即使配置候选和记忆候选来自同一次生成请求，两者仍分别接受下游验证和处理。

### 9.2 Long-term Memory 候选

Skill 只为模拟开始前已经存在的背景经历生成 Long-term Memory 候选。候选可以表达情景、知识、经验、关系印象或输入支持的其他长期类型，并保留：

* 目标记忆所有者。
* 来源片段和来源资格。
* 叙事视角与信息获得方式。
* 输入支持的时间精度。
* 关联实体及其解析状态。
* 主观确信、冲突和不确定性。

Skill 不生成 Working Memory、Recent Memory、Activation Set、前瞻性意图或认知连续状态。

### 9.3 主观实体档案候选

名称、称呼、属性、印象或关系等档案断言必须引用同一候选包中的 Long-term Memory 候选作为支持来源。没有长期记忆支持的档案断言不能输出。

档案候选表达目标角色的主观认识，不是对世界配置或被观察实体 Identity 的修改。冲突断言可以并存，并分别保留支持来源和主观确信。

### 9.4 认识方式

Skill 必须保持第一手经历、他人陈述、目标角色推测和外部记录之间的区别。听见一句话不等于相信其内容，世界内记录也不等于角色亲历了记录中的事件。

输入没有表达角色是否接受某项说法时，Skill 只能保留其接触到该说法，不得自动生成高确信知识或档案断言。

### 9.5 不允许补造的内容

Skill 不能为了形成生动记忆而补造：

* 输入没有提供的感官细节、对话、动作或心理活动。
* 更精确的时间、地点和参与者。
* 角色没有机会获得的信息。
* 对冲突材料的最终裁定。
* 把作者视角、全知叙述或世界事实自动变成角色视角。

## 10. 生成流程

配置生成 Skill 使用以下流程：

**接收结构化输入 → 核对版本与字段完整性 → 固定目标规范上下文 → 在字段语义内解释自然语言 → 解析显式引用与来源 → 生成候选 → 可选非权威预检 → 输出候选与诊断**

### 10.1 输入核对

Skill 首先确认输入包身份、工作模式、输入语义版本、目标规范版本、字段类型、对象归属和必需引用。输入结构本身无效时，不进入语义生成。

### 10.2 规范固定

一次生成使用固定的目标规范上下文。生成过程中规范版本发生变化时，当前结果仍绑定开始时的版本；下游必须按候选声明的版本验证，不能静默改用新版本。

### 10.3 字段内解释

Skill 只在字段类型授权的范围内理解自然语言。它可以从人物背景经历字段中提取事件和关系，但不能从同一文本推导未声明的身体规则；可以从规则说明字段中形成规则候选，但不能把写作示例当成有效规则。

### 10.4 候选生成

候选生成需要同时建立来源、引用、依赖、未决项和冲突关系。先生成某个值再丢弃来源的处理无效。

### 10.5 非权威预检

如果外部共享或领域验证能力可用，Skill 可以把候选提交预检并使用结构化诊断修正输出。预检不使候选生效，也不把验证规则转移给 Skill。

预检不可用时，Skill仍可以输出候选，但必须保留其尚未经过权威验证的状态。Skill 不能把自身格式检查声明为领域验证成功。

### 10.6 输出

Skill 输出结构化候选和结构化诊断后结束。保存输出、呈现给用户、收集批准或调用应用接口均属于下游系统。

## 11. 缺失、默认值与冲突

### 11.1 缺失信息

缺少必需信息时，Skill 标记缺失项、受影响产物和传递依赖。未受影响的分区继续生成。

Skill 不通过常识、同类作品惯例、模型偏好或其他项目资料填补缺失值。

### 11.2 默认值

只有输入明确请求使用规范默认值，并且目标配置类型确实声明该默认值时，Skill 才能生成默认结果。

字段缺失、空字符串、未确定或冲突都不等于请求默认值。默认值不存在或不适用于目标类型时返回诊断。

### 11.3 配置冲突

同一配置目标存在互不兼容的显式内容时，Skill 不能按输入顺序、文本篇幅或主观可信度静默选择。冲突项及其来源保持并列，并阻塞依赖唯一值的候选分区。

### 11.4 记忆冲突

合格来源对同一事件或实体给出不同描述时，可以生成分别溯源的记忆候选和冲突关系。记忆冲突不自动阻塞全部候选，因为角色可以持有不一致认识；但 Skill 不能擅自合并为唯一真相。

## 12. 来源与版本

### 12.1 来源链

候选的来源链至少能够回答：候选属于哪个输出包、由哪个输入对象和字段产生、使用了字段内哪个片段、经过了何种归纳、引用了哪个规范默认值，以及受到哪些未决项影响。

来源链服务后续验证、审阅和诊断，但本文不规定其界面呈现方式。

### 12.2 语义版本

输入字段语义、目标配置规范、领域扩展和记忆导入规范都必须版本化。Skill 不能混用不兼容版本，也不能在没有兼容声明时自行迁移输入。

### 12.3 重复生成

LLM 生成不要求在相同输入下产生逐字或逐字节相同的候选，但来源未变化且语义未变化的结果应保持可关联身份，便于下游比较。

重复生成不会覆盖旧候选或当前有效状态。候选保存和版本历史由下游系统负责。

## 13. 验证协作

### 13.1 配置验证

统一配置与规则基础设施拥有结构、引用、依赖、组合、权限和兼容性验证；各领域系统拥有自身领域不变量验证。Skill 只生成符合目标规范的候选，并消费这些系统返回的诊断。

Skill 不能宣布候选已经成为有效运行配置，也不能附加“跳过验证”或“强制应用”语义。

### 13.2 记忆验证

记忆系统拥有初始记忆候选的类型、来源、角色归属、实体关联、冲突和档案支持关系验证。候选通过验证后如何导入 Long-term Memory 和物化实体档案，属于记忆导入能力而非 Skill。

### 13.3 诊断驱动修订

Skill 可以接收外部验证诊断和原候选身份，生成修订候选。修订只能使用原输入、固定规范和诊断中公开的信息，不能为了消除错误而创造新的设计事实。

每次修订都是新候选结果。是否保留、比较或应用旧候选由下游系统决定。

## 14. 跨系统协作

### 14.1 与上游设计资料工具

上游工具负责把自然语言内容放入语义明确的结构化字段，并提供对象归属、来源类型和允许用途。上游不必预先提取最终配置项、记忆痕迹或实体断言。

Skill 不定义上游编辑器、文档导入、字段填写界面或自动分类方式。未被可靠分类的文本应在上游保持未确定，不能作为无类型输入传给 Skill。

### 14.2 与统一配置与规则基础设施

共享基础设施向 Skill 提供版本化配置规范、领域扩展清单、默认值、引用与规则词汇，并对候选执行权威验证。

Skill 不能注册扩展、编译规则、提交配置或修改当前有效版本。

### 14.3 与人物系统

人物系统验证候选角色配置及其子系统关联。人物创建不会自动调用配置生成 Skill，也不会把 Identity、人物小传或个人历史自动转换为记忆。

人物配置候选和初始记忆候选具有独立交接路径。创建角色与导入初始记忆的协调由后续应用系统定义。

### 14.4 与记忆系统

记忆系统提供允许的初始长期记忆类型、主观实体断言类型和导入验证能力。Skill 只生成候选，不能直接建立 Long-term Memory、语义索引或实体档案物化视图。

初始记忆不是从 Identity 字段默认派生。只有输入明确把自然语言字段声明为合格记忆来源时，Skill 才能执行提取。

### 14.5 与配置审阅及应用系统

独立的配置审阅及应用系统负责候选持久化、用户审阅、批准、权威验证编排、原子应用、版本管理和失败恢复。

本设计只要求候选和诊断具有足够的结构化来源与依赖信息，不定义下游如何展示字段、差异、冲突或验证结果，也不定义任何用户界面。

### 14.6 与第三方行为树组件

第三方组件负责具体节点、树运行、编辑和调试能力。系统只要求适配层满足已经确立的确定性、权限、黑板和身体计划边界。

Skill 根据第三方适配规范生成候选配置，不解释或生成系统未注册的私有节点语义。

## 15. 产品级概念接口

以下接口只定义交互责任和产品语义，不规定字段、协议或调用方式。

### 15.1 生成能力查询

查询 Skill 支持的输入语义版本、工作模式和目标规范兼容范围。结果不能被用作运行时领域扩展注册。

### 15.2 初始配置候选生成

接收结构化输入包和固定规范上下文，返回候选配置包及诊断。结果需要区分完整候选、部分候选、输入无效、规范不兼容和无法表达。

### 15.3 初始记忆候选提取

接收包含合格自然语言来源字段的结构化输入包、目标角色和记忆规范上下文，返回 Long-term Memory 与主观实体档案候选及诊断。

### 15.4 候选预检请求

把候选交给外部权威验证能力并取得结构化诊断。该接口不属于配置应用，也不改变任何当前状态。

### 15.5 诊断修订

接收原输入、原候选身份、固定规范和外部诊断，返回新的修订候选或无法修订结果。

### 15.6 候选导出

输出候选、来源、引用、依赖、冲突、阻塞项和版本信息。导出只产生数据，不指定保存位置、审阅方式或应用动作。

## 16. 结果与失败语义

Skill 至少区分：

* **完整候选：** 所请求范围均已生成，但仍等待下游权威验证和应用决定。
* **部分候选：** 独立分区已经生成，其他分区因明确阻塞项未生成。
* **输入无效：** 输入包、字段类型、归属、模式或引用不满足输入语义。
* **来源不合格：** 文本字段不允许用于请求的输出类型。
* **信息缺失：** 必需设计内容没有提供，也没有明确请求规范默认值。
* **输入冲突：** 配置目标存在尚未解决的互斥内容。
* **引用未解析：** 文本提及或显式引用不能唯一定位合法目标。
* **版本不兼容：** 输入语义、目标规范或领域能力不能共同使用。
* **无法表达：** 目标规范没有表达输入要求所需的类型或词汇。
* **预检拒绝：** 外部验证器拒绝候选，等待修订或上游设计调整。
* **生成失败：** Skill 未能形成可信的结构化结果，不能用猜测产物替代。

这些状态描述候选生成结果，不描述持久化、审阅或应用状态。

## 17. 验收场景

1. 合法结构化输入中的世界观自然语言字段可以生成有来源的首版世界配置候选，且不修改任何持久化状态。
2. 完整人物小传可以作为 Identity 字段输入并生成 Identity 候选，但不会因此自动生成初始记忆。
3. 同一人物小传被明确声明为目标角色的合格背景经历来源时，可以在初始记忆模式生成长期记忆候选。
4. 没有类型和归属的纯文本被拒绝，Skill 不根据标题或写作内容自行分类。
5. 字段缺失、空文本和未确定不会被解释为请求规范默认值。
6. 输入明确请求规范默认值时，输出记录默认定义来源；规范没有默认值时返回诊断。
7. 两个输入字段对同一唯一配置值给出冲突要求时，相关分区保持阻塞，不按输入顺序选择。
8. 一个领域存在阻塞时，与其没有依赖的其他领域仍能形成部分候选。
9. 输入要求未注册规则词汇时返回无法表达，不创建私有扩展。
10. 对话字段明确目标角色只听到其中一部分时，Skill 不为未听到的内容生成记忆。
11. 对话中的他人陈述保留为听闻，不自动形成角色亲历或高确信世界知识。
12. 两个合格来源对同一经历给出冲突描述时，生成分别溯源、可以并存的记忆候选。
13. 主观实体档案断言没有候选长期记忆支持时被拒绝生成。
14. 只有自然语言称呼而不能唯一解析实体时，不绑定猜测的实体引用。
15. 预检返回领域错误时，修订候选只能使用原输入和诊断，不能补造新事实。
16. 候选生成、预检、失败或重试均不创建角色、不导入记忆、不更新当前配置。
17. 输出不包含持久化路径、审批状态、应用命令或用户界面布局。
18. 第三方行为树不满足确定性或权限契约时，适配候选返回不兼容，而不是绕过约束。

## 18. 范围边界

本文不定义：

* 输入和输出的具体序列化格式、字段名称、文件扩展名或通信协议。
* 上游资料编辑器、文档导入器、自动字段分类或自然语言录入界面。
* 配置及候选的持久化方式。
* 用户审阅、差异呈现、批准、发布、回滚和其他界面流程。
* 权威配置验证器和记忆导入器的内部实现。
* 增量配置修改、配置迁移、已有运行状态适配或分支合并。
* 具体模型、提示词全文、采样参数或供应商能力。
* 第三方行为树的节点语言、行为内容、编辑器和调试器。
* 具体世界观、人物、身体数值、规则或初始记忆内容。

## 19. 设计约束总结

1. Skill 的输入和输出均结构化，但输入字段可以保存自然语言文本。
2. 结构化字段必须先确定文本的类型、归属、用途和允许输出，Skill 不负责猜测这些边界。
3. 上游不必预先把自然语言拆成最终配置项、记忆痕迹或实体断言。
4. Skill 只在字段语义范围内理解文本并生成有来源的候选数据。
5. 初始配置和初始记忆是两个明确模式，使用不同输出类型和下游路径。
6. Identity 和人物小传不会因为进入人物配置而自动成为初始记忆。
7. 初始记忆只来自明确合格的字段，并保留所有者、视角、认识方式和来源片段。
8. Skill 不补造缺失事实，不静默解决配置冲突，也不把记忆冲突裁定为唯一真相。
9. 只有目标规范声明的默认值、配置类型、引用和规则词汇可以进入候选。
10. Skill 可以消费外部验证诊断，但不拥有权威验证、持久化或提交权限。
11. 候选保存、用户审阅、批准和应用属于独立系统，本文不定义其用户界面。
12. 本阶段只支持首版生成，不支持增量修改、迁移或已有状态适配。
13. 行为树采用第三方组件，系统只保留适配契约，不详细设计其内部节点和工具。
