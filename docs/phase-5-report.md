# 阶段 5 报告：主观记忆闭环

- 日期：2026-09-24
- 依据：[阶段 5 详细执行计划](phase-5-execution-plan.md)、[记忆系统设计](memory-system.md)、`AGENT.md`
- 结论：运行中的正常实体已能从实际准入并使用的内容选择性形成近期记忆，在稳定 Tick 边界巩固为长期记忆，并经有限检索重新进入 Working Memory 影响认知决定。玩家和 AI 的记忆实例隔离；降级实体没有主观记忆。

## 1. 已实现

| 工作包 | 交付 |
| --- | --- |
| P5.0 | `agentlife.memory@1.0.0` 与 content 中的记忆规则参数；embedding 提供器、模型、地址和表示版本独立置于根目录 `config/agentlife.yaml`。各角色维护 Working、Recent、Long-term、主观档案及审计归档状态；存档版本 4 核对系统表示版本。索引从活动痕迹计算，不另存权威副本。 |
| P5.1 | Working Memory 按离散负荷与容量确定性裁剪，按模拟 Tick 到期删除；认知实际使用后才确认消费，编码先核验仍在 Working 的来源。一次性交接的发言和动作结果在决定机会结束后释放，避免重复送入认知。意图仍由认知持有。 |
| P5.2 | 认知提交带来源的编码候选，记忆服务验证角色归属、准入和实际使用后建立 Recent 痕迹与同版本语义向量。超窗未巩固痕迹退出活动记忆，关联断言同步失效；删除记录只保留在授权审计归档。 |
| P5.3 | 固定 Tick 边界与批量预算后由独立 Memory Agent 选择并概括 Recent；结果经来源校验后迁入 Long-term，活动 Recent 来源移除。主观名称等断言由认知明确提交，允许冲突并存，仅由活动痕迹支持。 |
| P5.4 | `memory_search` 按角色和活动状态过滤，合并结构词、有限关联、语义向量和当前锚点线索；可达性与抑制参与激活门槛。只向 Memory Agent 送有限候选，重排结果再经 Working 准入；认知明确标记实际使用后才强化。 |
| P5.5 | 可替换 embedding 端口；HTTP 适配支持 Ollama `/api/embed` 与 OpenAI 兼容 `/v1/embeddings`，痕迹与查询使用同一模型，进程内计算余弦相似度。请求失败可见并停止必要记忆处理。演示和自动测试使用确定性假提供器。 |
| P5.6 | 感知仅在足够分辨率时查询观察者本地档案；达到阈值才附加档案引用、首选称呼和置信度。内部锚点不增加识别置信度，不向感知返回完整档案。认知可提交有新观察与新编码支持的档案重连候选。 |
| P5.7 | 检索、编码、巩固、衰减和删除接入现有认知屏障，模型等待时 Tick 冻结，同轮计划统一交接。玩家通过 `M` 选择已准入观察并输入自己的记忆表述；监视面板只显示记忆数量与提供器诊断。提供 `phase5:verify`、`phase5:demo`。 |

## 2. 主要验收场景

阶段 5 自动测试覆盖：HTTP embedding 请求形状；角色间检索与档案隔离；已遗忘痕迹和失效断言无法召回；低置信度不返回身份；AI 实际消费观察后编码、后续巩固、保存加载、线索检索与回忆强化；玩家主动保留自己的准入观察。阶段 4 的认知、感知、TUI 等回归继续验证冻结屏障与授权视图。

演示入口 `pnpm phase5:demo` 使用假 embedding 与脚本化认知、记忆 Agent，按“观察 → 选择性编码 → 巩固 → 显式保存与加载 → 后续线索检索并回应”运行。真实模型与真实 embedding 服务不进入普通自动测试。

## 4. 边界与后续

- embedding 服务的安装、启动、模型下载和运行维护由用户负责，不属于本系统开发交付。根目录 `config/agentlife.yaml` 为 `/v1/embeddings` 选择 `openai-compatible` 提供器；Ollama `/api/embed` 仍可选择 `ollama` 提供器。
- 遵循已确认取舍：只有显式保存与加载；不设计自动重试、未完成记忆操作续做或异常恢复。模拟开始前的初始记忆候选验证与导入留待后续阶段；Fast Forward 完整调度和延后队列留待阶段 6。
- 主观身份关联以一位观察者对一个锚点的本地档案为限；复杂身份合并、拆分与冒充推理留待后续。结构与关联检索采用进程内有限扫描，适合当前 PoC 规模。

## 5. 最新会话复盘与修正

最新 session log 共 69 轮：18 次认知提交被拒，其中旧注意引用未在本轮 Working Memory 准入 12 次、行动计划与空闲承诺同时提交 4 次、记忆编码缺少本轮实际消费来源 2 次；第 28、39、67 Tick 各有一次认知失败。NPC 在从灯笼广场走到斜坡窑口后，收到原地点多人和物品逐一“不见了”的观察，同时重复提交了尚在执行的行走目标，因而误判原地点的东西消失并积累重复计划。

- 既有注意引用可持续沿用；新增注意仍须来自本轮准入观察。无本轮消费来源的可选编码候选被丢弃并记入轮次诊断，不阻断其他有效决定。若模型同时提交即时行动与空闲承诺，保留即时行动、舍弃空闲承诺并记入诊断；行动完成后可再决定等待。
- 按 content 声明的动作命令向认知提供用途说明，行走的 destination 只接受当前出口；同一出口的在途认知行走不再重复排队。当前动作与排队数量进入角色自己的情境摘要。
- 观察者换地点时清理旧地点追踪，但不把视野变化报告为原地点物品和人物“消失”；出口成为当前地点时明确报告“你到了”。提示词进一步区分未列出与不存在、行动与等待互斥、编码来源和避免重复发言。
- 修正后 TypeScript、Prettier 通过；认知、感知与记忆定向测试 33/33 通过；排除本机故障的旧版崩溃恢复用例后，全量回归 30 文件、303 通过、7 跳过。尚未以真实认知模型重放该会话，后续表现需由新会话观察。
