# 阶段 3 报告：上下文动作 TUI 竖切

- 日期：2026-09-22
- 范围：交互配置、玩家展示投影、上下文动作、参数向导、运行控制、正式 TUI、保存加载和演示入口
- 结论：阶段 3 的主要业务路径已经实现。动作栏只查询稳定状态和内容属性，不试运行规则或预测裁定；动作仍在下一 Tick 通过 Body 与 World 权威验证。

## 1. 交付内容

- `agentlife.interaction/action-command`：内容定义动作名称、顺序、别名、Body 动作、冲突策略和 Entity/文本参数。
- 演示内容：移动、拿取、放置、操作、挥手、说话六个动作命令。
- `PlayerView`：只包含玩家当前地点、同地点公开实体、持有物和玩家动作。
- 上下文动作查询：按身体能力、位置关系和内容属性筛选；查询不改变模拟状态。
- `SimulationController`：待接纳计划、单步、连续、暂停、单一定时器、保存与加载。
- `ContextActionBar`：左右选择、Enter 确认、空格运行/暂停。
- 一次性系统反馈显示在底部快捷键同行的右侧，2 秒后消失；新反馈覆盖旧反馈并重新计时。事件区仅追加临时玩家投影可观察到的世界事件。
- 连续运行中进入参数向导只造成临时暂停，提交或取消后自动恢复；显式暂停保持不变。
- 参数向导：Entity 使用 SelectList，文本使用 Input，Esc 返回。
- 管理入口：`/step`、`/run`、`/pause`、`/save`、`/load`、`/status`、`/monitor`、`/help`。
- 管理员面板：Entities、World、Scheduler、Memory 占位和 Diagnostics。

## 2. 关键语义

- 动作栏不调用规则引擎模拟结果，也不创建临时权威状态。
- 空房间没有可携带物时不显示拿取；没有持有物或支撑物时不显示放置。
- 参数完成只排入下一 Tick，Tick 不会因界面输入自动推进。
- 空格只在动作栏焦点切换运行状态；文本和管理输入中的空格保持普通字符语义。
- 连续运行中确认动作会先安全暂停，再按稳定状态建立参数会话。
- 文本输入作为 ActionStep 的不透明 `inputs` 保存；BodyService 不解释它。
- 普通视图和 Entity 候选不读取管理分类、远处状态或行为树黑板。

## 4. 已知限制

- 阶段 3 展示投影不是正式感知；不会表达光照、遮挡、连续观察或身份置信度。
- 文本说话只随动作保存和展示，不触发其他角色认知。
- 动作栏条件只用于发现候选，不保证正式裁定成功。
- 当前参数文本使用 Pi TUI 单行 Input；正式自然语言编辑器留到阶段 4。
- Memory 面板只显示后续阶段占位。
- Windows Terminal 的最终人工清单仍需在真实交互终端中执行。
