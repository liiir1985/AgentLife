# 统一配置与规则基础设施设计

## 1. 文档目的

本文定义统一配置与规则基础设施的产品级模型、职责边界和运行语义。该基础设施为世界、人物、身体以及后续感知、认知、记忆和时间调度系统提供共同的配置、声明式规则、编译、索引、确定性求值与追踪能力。

本文描述的是“各子系统如何使用一致的配置和规则机制”，不定义任何具体世界、角色、身体指标、感知算法、认知策略或记忆内容。本文不固定配置文件格式、编程语言、存储方案、类结构、协议字段和具体数值。

## 2. 设计目标

统一配置与规则基础设施需要保证：

* 所有运行时子系统使用一致的命名空间、版本、引用、组合、覆盖和验证机制。
* 能够确定表达的条件、映射和过程复用同一套受限规则能力，不在各领域重复实现近似规则引擎。
* 规则运行只读取显式授权的输入，并对相同版本和相同输入产生相同结果。
* 配置、规则定义、编译结果和运行状态彼此分离，加载配置不能覆盖已经形成的运行状态。
* 各领域系统继续独占自己的语义、权威状态、不变量验证和提交权限。
* LLM 和配置生成工具只能产生候选配置或规则，必须经过原子配置更新才能生效，不能直接修改权威状态。
* 新规则的输入、完整验证、编译和生效构成一个原子操作，失败时当前有效配置完全不变。
* 配置来源、求值过程、候选结果和版本关系可以追查、诊断和恢复。

本系统采用 **配置能力必须复用、规则能力按需复用** 的原则。所有子系统必须接入共享配置能力；只有适合确定性声明表达的逻辑才接入规则内核。

## 3. 职责边界

### 3.1 基础设施负责

统一配置与规则基础设施负责：

* 解析配置包并检查通用结构和类型。
* 处理命名空间、稳定标识、显式版本和引用。
* 按确定顺序应用默认值、组合和覆盖。
* 管理领域扩展的注册和兼容性检查。
* 验证规则的通用结构、读取依赖、效果声明和组合方式。
* 编译有效规则，建立触发索引和稳定依赖顺序。
* 基于显式输入快照和模拟时间执行确定性求值。
* 产生候选效果、求值结果、诊断和完整追踪信息。
* 原子更新当前有效运行配置，并维护其单一版本身份。
* 持久化自身拥有的配置、编译产物、索引和追踪信息，并为整体保存与恢复提供配置版本核对能力。

### 3.2 基础设施不负责

统一配置与规则基础设施不负责：

* 定义世界事实、人物身份、身体状态、感知结果、认知内容或记忆语义。
* 直接创建、修改或提交任何领域系统的权威状态。
* 替领域系统判断候选效果是否满足最终领域不变量。
* 运行 LLM、解释自然语言或执行任意脚本代码。
* 让规则求值器在求值期间读取机器当前时间、访问外部服务或执行文件、网络、数据库 I/O。
* 产生随机数、概率抽样或依据隐藏环境信息改变结果。
* 推进模拟时钟、安排 Tick 阶段或直接启动认知任务。
* 将调试追踪、控制来源或隐藏因果暴露为角色感知、认知或记忆。

上述 I/O 限制只针对确定性规则求值器。配置加载、当前配置更新、编译产物缓存、追踪落盘和系统快照持久化可以由求值器之外的基础设施组件通过明确接口完成。外部读取结果只有成为显式、版本化输入后才能参与后续求值。

## 4. 信息与产物分层

### 4.1 领域扩展定义

领域扩展定义描述某个子系统允许配置和求值的语言边界，包括配置类型、可读取视图、条件与触发器词汇、候选效果类型、输出类型、组合方式、领域验证入口及兼容要求。

扩展定义只声明能力，不保存领域运行状态，也不授予共享基础设施提交状态的权限。

### 4.2 源配置包

源配置包是设计时输入，包含自身身份与运行配置版本、配置定义、领域扩展定义、引用、默认值、组合项、覆盖项及规则定义。

源配置包可以由人工或配置生成 Skill 产生。Skill 的输入字段可以保存自然语言，但字段类型、归属和用途必须已经明确；来源不同不改变验证和原子更新要求。

### 4.3 解析后配置

解析后配置是完成引用解析、默认值应用、组合与覆盖后的不可变有效配置视图。它保留各值来源及处理顺序，供领域验证、实例创建和诊断使用。

解析后配置不是运行状态。角色、身体或世界实例创建后形成的变化不能通过再次解析初始配置被覆盖。

### 4.4 编译规则集

编译规则集是当前运行配置的内部产物。它包含可执行的受限表达、触发索引、读取依赖、效果目标、稳定求值顺序及来源信息。

编译规则集不能脱离所属运行配置独立生效。规则增加、删除或修改都会形成新的运行配置版本。

### 4.5 求值输入快照

求值输入快照是领域系统为一次求值提供的只读输入，包括明确的状态版本、允许字段、触发事实、显式模拟时间以及请求身份。快照只包含本次求值所需的最小信息。

### 4.6 候选结果与追踪

候选结果描述规则计算建议产生的领域效果或过程操作，不具有权威状态效力。求值追踪记录使用的版本、读取内容、命中规则、条件结果、组合顺序、输出和拒绝原因。

## 5. 统一配置模型

### 5.1 命名空间与稳定标识

每个配置包、配置定义、规则和领域扩展都具有所属命名空间及稳定标识。引用必须能够唯一定位目标，不能依赖加载顺序、文件位置或显示名称碰巧相同。

跨命名空间引用需要由目标明确公开并由引用方声明依赖。未公开目标、循环包依赖或无法唯一解析的引用均使配置无效。

### 5.2 单一运行配置版本

对运行时和求值接口只暴露一个运行配置版本。该版本唯一确定解析后的配置内容、规则定义及编译产物、领域扩展语义和确定性运算语义。

配置内容、规则或领域扩展的任何有效变化都会形成新的运行配置版本。实现内部可以为编译产物或扩展组件保留身份以支持缓存和诊断，但调用方不分别选择这些版本，它们也不能独立于运行配置生效。

当前有效版本的内容不得被原地覆盖。相同版本标识对应不同完整内容时应视为完整性错误。

### 5.3 默认值、组合与覆盖顺序

共享解析流程采用固定顺序：

1. 确认根配置及其显式依赖。
2. 解析引用并建立无环依赖顺序。
3. 应用对应配置类型声明的默认值。
4. 按声明顺序组合模板或配置片段。
5. 应用当前配置包的显式覆盖。
6. 形成完整解析结果并执行共享及领域验证。

默认值只能来自配置类型或明确引用的模板，不能由引擎根据名称、上下文或自然语言猜测。覆盖必须指向允许覆盖的目标，并保留被覆盖值和新值的来源。

列表、集合、映射和标量如何组合必须由对应配置类型声明。没有明确合并语义的重复定义不能采用“后加载者获胜”等隐式规则。

### 5.4 引用解析

引用解析需要验证目标存在、目标类型正确、命名空间可见、语义兼容及依赖无环。引用结果固定在生成的运行配置中，运行时不能因外部内容变化而自动漂移。

### 5.5 配置与运行状态分离

配置描述实例可以具有的结构、机制和初始要求；运行状态描述实例已经发生的实际变化。配置更新或重新加载都不能直接改写既有实例状态。

已有实例状态如何适应新配置属于对应领域的验证责任。配置更新不能倒改已经提交的状态或过程参数；后续求值统一使用更新后的当前有效配置。

## 6. 领域扩展机制

### 6.1 扩展注册内容

每个领域扩展至少注册：

* 自身身份及与共享内核的兼容要求。
* 支持的配置类型和通用结构约束。
* 可供规则读取的只读视图及字段类型。
* 支持的触发器、条件、运算和候选效果类型。
* 输出目标允许的类型、范围及组合方式。
* 领域验证入口和可返回的结构化诊断类别。
* 与其他扩展协作时明确公开的最小接口。

### 6.2 权限隔离

扩展只能读取注册视图中明确允许的内容，只能产生注册的候选效果。一个领域扩展不能因为能够引用另一个领域的类型，就获得读取其内部状态或提交其效果的权限。

跨领域规则需要分别使用相关领域公开的只读视图，并把候选结果交给拥有目标状态的领域系统验证和提交。共享基础设施不能代替跨领域事务协调。

### 6.3 兼容性

运行配置更新时需要验证共享内核、配置内容和领域扩展语义能够共同运行。扩展新增词汇不能在同一运行配置版本内改变已有词汇的语义；语义发生变化时必须形成新的运行配置版本。

### 6.4 扩展能力限制

领域扩展可以增加受限类型、条件、映射和候选效果，但不能借扩展机制注册任意代码、隐式 I/O、随机源、机器时间或直接状态写入能力。

## 7. 声明式规则模型

### 7.1 规则组成

一条规则可以声明：

* 规则身份、所属领域和来源。
* 能够使规则成为候选的触发器。
* 求值所需的显式读取依赖。
* 必须成立的受限条件。
* 条件成立时产生的候选效果或过程操作。
* 多个输出作用于同一目标时采用的组合方式。
* 与其他规则或派生量之间的依赖关系。
* 适用的配置范围、扩展要求及输入状态要求。

规则不能包含自由文本指令作为运行时可执行逻辑。说明文本可以用于文档和诊断，但不参与求值。

### 7.2 触发器

触发器用于缩小候选规则集合，可以基于已注册的请求类型、事实变化类型、指标变化、过程到期、显式时间条件或其他领域事件类别。

触发器只决定哪些规则需要进一步检查，不代表条件已经成立，也不直接产生效果。

### 7.3 条件与读取依赖

条件只能使用规则声明并由领域扩展授权的输入。所有可能读取的字段、关系、派生量和模拟时间需求必须在编译时可识别。

条件不能因为字段缺失而隐式选择默认真值。缺失输入必须依据类型定义产生明确的不匹配、无效输入或无法求值结果。

### 7.4 候选效果

候选效果描述建议由领域系统验证和提交的变化。效果需要声明目标领域、目标类型、计算值、来源规则、依赖状态版本和效果身份。

共享基础设施不把候选效果解释为已经发生，也不生成领域事件记录。

### 7.5 效果映射

第一阶段共享内核至少支持：

* 硬阈值。
* 分段常量。
* 分段线性。
* 优先级、最小值、最大值、加法和乘法组合。

数值类型、单位、边界包含关系、舍入、溢出和区间外行为必须由类型或映射定义明确，不能依赖运行平台的隐式行为。

### 7.6 持续过程

规则可以产生建立、推进、暂停、结束或取消持续过程的候选操作。过程建立时已经计算并提交的参数成为对应领域的过程状态，不因后续配置更新而被倒改。

共享内核只根据显式到期输入、当前有效运行配置和当前快照计算过程的下一候选变化，不自行推进模拟时间，也不直接维护领域过程状态。

## 8. 确定性求值语义

### 8.1 完整求值上下文

每次求值必须固定：

* 当前有效运行配置版本。
* 输入状态版本和只读快照。
* 触发请求或过程身份。
* 由时间系统提供的显式模拟时间。

一次已经开始的求值始终使用开始时取得的运行配置和输入快照完成。配置更新只影响更新成功后开始的新求值，不会使单次求值看到混合内容。

### 8.2 禁止的隐式输入

求值期间禁止使用：

* LLM 或自然语言解释结果。
* 随机数和概率抽样。
* 机器当前时间、时区或运行耗时。
* 文件、网络、数据库或其他外部 I/O。
* 未在规则读取依赖中声明的状态。
* 容器遍历顺序、并发完成顺序或加载顺序等实现偶然性。

不确定结果必须由领域系统或外部裁定机制形成带来源的显式输入，再交给规则求值。

### 8.3 稳定顺序

候选规则先由触发索引定位，再依据编译出的依赖顺序执行。没有数据依赖但可能影响可观察输出顺序的项目，需要使用已声明的稳定顺序或稳定标识作为最终顺序依据。

不能用运行时发现顺序解决规则优先级或写入冲突。

### 8.4 相同输入语义

在相同运行配置版本、输入快照和模拟时间下，求值必须产生相同的结果集合、组合结果、顺序和追踪内容。

该要求针对已加载规则执行，不要求相同提示使 LLM 再次生成完全相同的候选规则。

## 9. 验证、编译与索引

### 9.1 验证阶段

配置与规则按以下顺序验证：

1. **结构验证：** 必需组成、类型和受限表达合法。
2. **引用验证：** 目标存在、类型匹配、命名空间可见且语义兼容。
3. **依赖验证：** 配置组合、派生量和规则依赖能够形成稳定顺序。
4. **组合验证：** 多来源输出具有明确且合法的组合方式。
5. **权限验证：** 读取视图和候选效果均已由领域扩展授权。
6. **领域验证：** 各领域检查自身语义、不变量和适用范围。
7. **兼容性验证：** 共享内核、配置内容、规则和扩展语义能够共同运行。

任一阶段失败都不能改变当前有效配置。诊断需要定位配置或规则身份、失败阶段、相关引用和来源。

### 9.2 循环处理

配置引用、规则依赖和派生量依赖必须在编译前检查循环。无法证明能够按明确有限语义稳定求值的循环一律拒绝。

第一阶段不提供通过反复迭代直到收敛来接受循环规则的隐式机制。

### 9.3 编译

编译把有效声明转换为不可变运行产物，包括：

* 已固定的引用和类型。
* 触发器到候选规则的索引。
* 规则和派生量的稳定依赖顺序。
* 读取集合、输出集合及组合计划。
* 运行配置身份、来源和追踪所需元数据。

编译不预先执行依赖运行状态的条件，也不赋予候选效果提交权限。

### 9.4 增量索引

运行时根据实际变化、请求类型和到期过程查询索引，只检查可能受影响的规则。没有相关触发、没有变化的实体和未到期过程不参与求值。

新的运行配置可以在内部复用语义未变化的编译产物，但复用不能改变新版本的完整性身份和追踪结果。

## 10. 运行时求值流程

一次规则求值遵循统一路径：

**固定运行配置与输入快照 → 查询触发索引 → 检查读取前提 → 按稳定顺序求值条件 → 计算并组合输出 → 生成候选结果与追踪 → 交还领域系统验证和提交**

### 10.1 输入确认

基础设施首先固定当前有效运行配置，并确认输入快照满足编译时声明的读取需求。状态版本已经变化时，不使用旧快照补算当前结果。

### 10.2 条件与映射求值

只有索引命中的规则进入条件检查。未满足条件的规则可以在追踪中说明未命中原因，但不产生效果。

### 10.3 候选效果组合

作用于同一组合目标的输出按照编译计划统一组合。组合完成后检查通用输出类型和范围，但最终领域合法性仍由目标领域检查。

### 10.4 领域提交

领域系统接收候选结果后，重新确认依赖状态版本和领域不变量，再决定接受、拒绝、部分接受或要求重新求值。只有领域系统正式提交后，变化才成为权威状态。

如果多个领域都需要改变，各领域分别拥有自己的候选结果和提交责任。跨领域原子性由上层协调者定义，不由规则基础设施隐式提供。

## 11. 多来源组合与冲突

### 11.1 组合目标

领域扩展需要定义哪些输出属于同一组合目标，以及该目标允许哪些组合方式。名称相同但语义不同的输出不能仅凭名称被组合。

### 11.2 支持的组合方式

第一阶段通用组合方式包括：

* **优先级：** 采用唯一最高优先级来源；最高优先级并列且结果不一致时视为冲突。
* **最小值或最大值：** 对兼容数值或有序值求唯一结果。
* **加法或乘法：** 按类型声明的单位、边界、舍入和溢出语义组合。

领域可以限制某种通用组合方式是否适用于特定输出，但不能在同一运行配置版本中重新定义同一组合运算的含义。

### 11.3 冲突处理

能够在加载时发现的写入歧义、缺失组合方式或不兼容类型必须拒绝配置。只有依赖运行输入才出现的冲突，需要返回结构化冲突结果，不能静默选择某一来源。

领域状态之间的业务冲突由领域系统处理；共享层只报告规则输出层面的冲突。

## 12. 原子配置更新与运行中新增规则

### 12.1 原子操作边界

候选配置或新规则的输入、完整解析、共享验证、领域验证、编译和生效构成一个原子配置更新操作。外部只能观察到更新前的完整配置或更新后的完整配置，不能观察到中间状态。

### 12.2 成功与失败

更新过程在不可见的临时结果中构造新的完整运行配置。任何验证或编译步骤失败时，返回结构化诊断，当前有效配置完全不变，不需要执行领域回滚。

全部步骤成功后，一次原子提交同时保存新运行配置并使其成为当前有效版本。持久化必须保证提交前崩溃仍使用旧配置，提交完成后恢复得到完整新配置，不存在半生效状态。

### 12.3 对运行求值和过程的影响

已经开始的单次求值使用开始时取得的配置快照完成；原子提交之后开始的新求值统一使用新配置。

未结束过程不会永久绑定旧规则。过程已经提交的参数和进度属于领域状态，不被新配置倒改；过程下一次需要规则判断时使用当前有效配置。领域系统发现新配置已无法合法处理现有过程时，应产生明确失败或停止结果，而不是回退使用旧规则。

### 12.4 LLM 生成规则

当世界或未来其他领域请求 LLM 补充规则时，LLM 只能返回候选规则或无法表达结果。候选规则必须通过同一个原子配置更新操作才能生效，不能直接追加到当前有效配置。

一次性状态变更不是配置更新。它仍需使用领域允许的候选效果表达，并由领域系统验证和提交。

## 13. 时间、过程与 Tick 边界

模拟时钟由时间系统维护。共享基础设施只能读取求值上下文中显式提供的模拟时间、Tick 身份或到期信号，不能查询机器时间或自行推进时间。

持续过程的到期索引可以由共享编译能力生成，但何时唤醒过程、Tick 各阶段顺序、暂停、恢复和追赶语义由时间与整体调度系统决定。

Tick 内只执行已经编译的规则和已经建立的过程，不等待 LLM。配置更新不会改变已经开始的单次求值；更新完成后的下一次求值读取新的当前有效配置。

## 14. 追踪、诊断与可观察性

### 14.1 配置来源追踪

解析结果需要能够说明一个有效值来自默认值、模板组合还是显式覆盖，并关联对应配置包和版本。被覆盖内容仍应可供授权诊断查看。

### 14.2 求值追踪

一次求值至少能够追踪：

* 请求、过程或触发来源。
* 使用的运行配置版本。
* 输入状态版本和显式模拟时间。
* 索引命中的候选规则。
* 实际读取的授权字段及条件结果。
* 映射、依赖和组合顺序。
* 产生的候选效果、冲突和拒绝原因。

追踪内容应区分“规则没有被触发”“条件不成立”“输入缺失”“领域拒绝”和“状态版本过时”等不同原因。

### 14.3 信息隔离

完整追踪属于授权管理和调试信息。领域系统可以从中提取适合作为客观事件来源的信息，但不能把隐藏规则、内部数值、控制来源或客观因果自动提供给角色认知和记忆。

## 15. 保存、恢复与一致性

### 15.1 保存内容

统一基础设施持久化自己拥有的内容，包括：

* 当前有效运行配置及其版本。
* 对应的编译产物和触发索引，或可重新构建它们的完整配置内容。
* 未决求值或候选结果的请求身份与依赖状态版本。
* 已经提交或消费的效果身份。
* 按产品需要保留的求值追踪和诊断记录。

世界、人物、身体、感知、认知、记忆和时间调度分别拥有并保存自己的权威状态。整体保存协调器在一致的保存边界收集各领域快照及当前运行配置版本，再通过持久化接口写入存储。统一基础设施不保存各领域权威状态的第二份副本。

### 15.2 恢复核对

恢复前必须定位快照记录的运行配置版本，并确认内容完整性及其与各领域快照兼容。若希望使用不同配置恢复，必须作为显式配置更新或领域迁移处理，不能静默替换。

恢复后未结束过程保留已经提交的参数和进度，后续求值使用恢复后的当前有效配置。已提交效果、已消费候选结果和已经结束的过程不能重复执行。

### 15.3 版本过时

延迟候选结果提交时，如果依赖的领域状态版本已经变化，领域系统应拒绝或要求基于新快照重新求值。配置版本是否已经更新不影响开始于更新前的单次求值完成，但旧结果不能覆盖已经变化的领域状态。

## 16. 子系统接入边界

### 16.1 感知系统

感知系统必须使用统一配置定义感官通道、感知材料类型、实体感知投影、分辨率与粗化映射、过滤条件、映射引用和策略参数。

确定性的可达性条件、阈值、遮挡结果输入、感官效率修正、显著度、细节分辨率、可观察字段投影和材料筛选可以使用规则内核。投影必须采用授权字段白名单，不能通用序列化完整领域对象。注意选择、有限观察组织及角色最终获得的感知内容仍由感知系统负责。规则只能产生候选描述或材料，不能直接写入感知流、认知或记忆。

### 16.2 认知系统

认知系统必须使用统一配置描述认知能力约束、允许的输入输出类型、意图召回与生命周期参数、等待边界和领域要求。

确定性的认知参与许可、持续决定条件和认知需求条件可以复用规则内核。意图候选的相关性、可达性、召回阈值、实际使用强化、衰减、遗忘阈值以及超出 Working Memory 预留容量后的裁剪也可以使用显式、版本化输入确定性求值。

等待期限可以依据等待类型、Identity 授权视图中明确结构化的修正项、当前情境和身体状态求值，并必须受全局硬上限约束。规则不能解释 Identity 自由文本。规则只能返回允许期限、候选资格或衰减结果，不能形成意图、解释主观承诺度、替角色完成多意图竞争或直接产生动作。LLM 推理、意图形成、记忆片段的主观解释、权衡和决定调整不进入确定性规则内核。AI 认知与用户输入解释形成的身体计划仍需由身体系统验证。

### 16.3 认知调度

认知调度必须使用统一配置表达认知需求来源、参与资格、明确条件和规则引用，可以复用触发索引和条件求值。

规则求值只能产生认知需求建议。参与者集合、全局认知屏障、AI 模型调用、用户等待或跳过、失败重试和本轮完成确认由认知调度器负责。现实计算层可以并发取得多个角色的决定，但规则和调度器都不能在必要决定完成前推进模拟时间。

### 16.4 记忆系统

记忆系统必须使用统一配置描述认知块类型与离散负荷、Working Memory 总容量、意图候选预留容量及未使用预留的处理方式、快速衰减、Recent 时间窗口、巩固触发、实体识别策略、检索索引、关联扩展、语义提供器引用、相关性组合、可达性、抑制和召回阈值。

确定性的容量准入、编码资格、巩固条件、感知分辨率接入、身份识别置信度、结构匹配、相关性组合、综合激活、衰减和运行时删除条件可以复用映射与规则。规则输入必须是显式、版本化的状态，不能读取自由文本含义、完整记忆库或审计归档。

语义相似度是记忆领域的必需能力，但具体模型和索引实现不属于规则内核。配置必须标识语义提供器及表示版本；不兼容表示不能在一次求值中混合。共享基础设施可以验证策略引用和组合参数，不能生成语义表示、调用记忆 Agent、重排候选或提交索引迁移。

记忆系统仍独占 Working Memory、记忆痕迹、实体档案、关联、记忆可达性、抑制和激活状态；认知系统独占前瞻性意图及其生命周期。共享检索能力必须通过类型和索引命名空间区分意图与记忆。开放语义查询、受限 Agent 重排、巩固摘要、认知对记忆片段的临时解释和主观实体断言不进入共享确定性内核。

### 16.5 时间与整体调度

时间与整体调度系统必须使用统一配置描述固定 Tick 时长、更新阶段、活动检查、目标 Tick、连续模式配速、Fast Forward 批次、主要实体标记、实体能力层级、行为树引用、离屏策略、传播上限、停止条件和保存检查点。

实体能力配置采用递进组合：普通动态实体提供世界更新基础；降级实体在此基础上增加身体执行、行为树和有限黑板；正常实体保留共同基础并以完整感知、认知和记忆模块替换行为树决策模块。普通动态实体不能配置自主决策入口，降级实体不能引用认知、主观记忆或 LLM，正常实体不能同时启用行为树与完整认知自主来源。

主要实体标记与正常能力层级必须分别验证。普通动态实体和降级实体必须非主要。行为树的局部世界视图和身体视图使用显式白名单；读取完整 Ground Truth、其他角色私有状态、主要标记、控制来源或调试视图的配置必须拒绝。

Fast Forward 配置不得启用 AI 认知、用户输入解释、记忆 Agent、语义重排、规则生成或任何其他 LLM。需要模型的记忆任务只能引用明确的受保护延后策略，不能通过“降级”配置转为隐藏模型调用或事后经历补写。

时间系统独占模拟时钟、运行模式和 Tick 阶段顺序，并在规则或认知调度建立屏障时停止推进。共享基础设施只处理显式 Tick、模拟时间、活动条件和目标 Tick，不能自行推进时间、跳过 Tick、解除屏障、运行行为树或决定跨系统提交顺序。

### 16.6 配置生成 Skill

配置生成 Skill 接收字段语义、归属和用途均已明确的结构化输入。字段值可以是世界观、人物小传或规则说明等自然语言文本；Skill 在字段语义范围内理解文本并使用共享配置规范、可用领域扩展清单和结构化验证诊断生成首版候选配置。输入不要求预先拆成最终配置项，但无类型、无归属的任意纯文本不能直接进入 Skill。

Skill 只输出结构化候选和诊断，不持久化、不审阅也不应用配置。生成结果必须先通过共享验证，再通过各领域验证；候选保存、用户审阅、验证编排和原子应用由独立系统负责。Skill 不能注册新的运行时词汇、绕过原子配置更新、执行迁移或绕过领域确认。

初始记忆提取是同一 Skill 的独立模式，但其产物不是源配置包，也不进入配置原子更新。该模式的候选由记忆系统验证和导入，配置基础设施只核对其中明确声明的配置版本依赖。

具体输入输出及生成边界见[配置生成 Skill 设计](configuration-authoring-skill.md)。

## 17. 与已设计子系统的协作

### 17.1 与世界系统

世界系统注册允许读取的事实视图、世界触发器和候选世界效果，并负责世界不变量、原子提交及事件记录。

基础设施为世界规则提供解析、编译、索引和确定性求值。缺失规则经 LLM 补充后，只有通过原子配置更新才能生效；基础设施不能直接把候选结果写入 Ground Truth。

### 17.2 与人物系统

人物系统使用共享配置能力解析角色配置、身体模板引用、组合、覆盖和版本。人物系统负责角色必需组成、控制来源隔离、Identity 更新权限及生命周期验证。

共享基础设施不能依据配置直接创建角色或覆盖角色运行状态。

### 17.3 与身体与行动系统

身体系统注册器官、能力、资源、指标、模式、身体过程和身体效果类型，复用共享映射、组合、依赖求值和追踪能力。

基础设施只计算候选身体效果和派生结果。身体系统负责动作状态、指标、资源、模式、不变量验证和正式提交。

## 18. 产品级概念接口

以下接口只定义交互责任和产品语义，不规定字段、协议或调用方式。

### 18.1 领域扩展注册

注册配置类型、读取视图、规则词汇、候选效果、组合方式和领域验证入口。结果需要区分成功、身份冲突、语义不兼容、越权能力和不受支持语义。

### 18.2 配置解析与验证

接收根配置包及显式依赖，完成默认值、组合、覆盖和引用解析，再依次执行共享与领域验证。失败返回结构化诊断，不产生可提交的运行配置。

### 18.3 规则编译

接收已通过验证的规则定义，建立读取集合、依赖顺序、组合计划和触发索引。编译失败不能保留部分可运行规则集。

### 18.4 原子配置更新

接收候选配置或规则，以当前有效配置为基础完成解析、验证和编译。全部成功时一次提交新的当前有效运行配置；任一步骤失败时返回诊断且不改变当前配置。

### 18.5 确定性求值

接收求值开始时固定的当前运行配置、输入状态快照、触发来源和显式模拟时间，返回候选效果、条件不成立、冲突、输入无效、状态版本过时或无法表达等结果及追踪。

### 18.6 追踪与诊断查询

为授权工具查询配置来源、编译依赖、规则命中、组合过程和失败原因。该接口不能作为角色运行时信息入口。

### 18.7 当前配置与版本查询

查询当前有效运行配置及版本，并定位保存快照记录的历史配置版本，用于追踪、恢复核对和显式迁移判断。

### 18.8 保存与恢复核对

验证保存状态中的运行配置版本、领域快照兼容关系和效果消费身份。缺失依赖、内容不一致或重复消费风险必须阻止恢复继续。

## 19. 结果与失败语义

基础设施至少区分：

* **有效：** 配置或规则通过全部验证和编译，可以由原子更新操作提交生效。
* **候选结果：** 求值成功形成效果建议，等待领域验证和提交。
* **条件不成立：** 规则适用范围明确，但当前输入不满足条件。
* **无匹配规则：** 触发索引中没有能够处理当前请求的规则。
* **输入无效：** 必需输入缺失、类型错误或不属于授权视图。
* **规则冲突：** 多个输出无法按声明方式得到唯一结果。
* **状态版本过时：** 请求依赖的领域状态已经改变。
* **配置不可用：** 当前或恢复所需的运行配置缺失、损坏或语义不兼容。
* **领域拒绝：** 候选结果通过共享求值，但未通过领域不变量验证。
* **无法表达：** 当前配置类型、规则词汇或候选效果语言不足以表示需求。

这些结果不能用单一“失败”替代，因为调用方需要据此决定重新求值、请求补充规则、修复配置或停止恢复。

## 20. 验收场景

1. 世界、人物、身体及未来子系统的配置能够通过同一套命名空间、版本、引用和诊断机制加载。
2. 角色配置引用身体模板并提供实例覆盖时，解析顺序固定且每个有效值来源可追查。
3. 缺失引用、跨命名空间越权引用、包依赖循环和不兼容扩展语义在配置更新生效前被拒绝。
4. 后续领域扩展可以增加自己的配置与规则词汇，但不能读取未授权状态或提交其他领域的权威效果。
5. 相同运行配置版本、输入状态及模拟时间重复求值时，得到相同结果和追踪顺序。
6. 规则不能读取机器时间、随机数、外部 I/O、LLM 或未声明字段。
7. Tick 只执行已编译规则和已建立过程，不调用 LLM，也不扫描全部规则。
8. 多来源效果没有组合方式、最高优先级并列冲突或依赖无法稳定排序时，配置更新不能生效。
9. 数值映射未声明边界、舍入或区间外行为时不能通过验证。
10. 世界规则只能产生候选世界效果，未经世界验证和提交不能成为 Ground Truth。
11. 身体映射可以复用阈值、分段常量和分段线性，并由身体系统提交最终派生状态。
12. 新规则的输入、验证、编译和生效为一个原子操作，失败时当前配置完全不变。
13. 配置更新期间崩溃时，恢复结果只能是完整旧配置或完整新配置，不存在半生效状态。
14. 已经开始的单次求值使用原快照完成，更新成功后开始的新求值统一使用新配置。
15. 已有过程保留已经提交的参数和进度，后续规则判断使用当前有效配置。
16. 延迟候选结果依赖的状态已经变化时，不能覆盖新状态。
17. 感知规则只能产生感知候选材料，不能直接形成认知或记忆。
18. 认知唤醒规则只能产生建议调度，不能直接调用 LLM 或形成意图。
19. 记忆规则只能产生候选记忆操作，不能替代认知在同一次决策调用中对记忆片段的主观解释。
20. 时间条件只能使用显式模拟时间，基础设施不能自行推进时钟。
21. 配置生成 Skill 的输出不能绕过共享验证、领域验证和原子配置更新流程。
22. 完整求值追踪可供授权诊断使用，但不会自动进入角色感知、认知或记忆。
23. Working Memory 容量、离散负荷、替换优先级和快速衰减可以由相同确定性输入重复求值得到唯一结果。
24. 记忆相关性、可达性和抑制分别作为显式输入组合，规则不能用单一隐藏分数替代全部语义。
25. 语义提供器或表示版本不兼容时配置或检索必须明确失败，不能静默混合分数。
26. 规则可以计算身份识别置信度和召回阈值，但不能借实体锚点读取真实身份或完整主观档案。
27. 相同意图状态、情境、配置版本和模拟时间产生相同的候选资格、可达性、衰减及容量裁剪结果。
28. 规则不能把相关性最高或承诺度最高的意图直接指定为角色当前目标。
29. 意图候选预留容量不能突破 Working Memory 总容量，也不能无限挤出当前观察。
30. 等待期限求值不能超过全局硬上限；到期结果只能提出认知需求，不能直接生成动作。
31. 主要实体标记与正常能力层级可以独立配置，具有认知实例不会自动成为主要实体。
32. 普通动态实体具有自主决策入口、降级实体被标记为主要或引用认知与主观记忆、正常实体同时启用行为树和完整认知时，配置不能加载。
33. 行为树局部视图不能读取完整 Ground Truth、私有认知、主观记忆、控制来源或调试信息。
34. Fast Forward 配置不能启用任何 LLM；缺失规则只能先退出快进再进入规则解析流程。
35. 固定 Tick 时长、阶段和快进策略使用单一运行配置版本，运行期间不能静默改变。

## 21. 范围边界

本文不定义：

* 具体配置序列化格式、文件扩展名或协议字段。
* 编程语言、类结构、数据库、缓存和部署方式。
* 具体世界规则、身体数值、感知参数、认知策略或记忆算法。
* LLM 提示、规则生成算法和配置生成 Skill 的具体实现。
* 候选配置的持久化、用户审阅、批准、应用和相关用户界面。
* 概率规则、随机选择、脚本沙箱或任意用户代码。
* 跨机器执行的位级重放要求和 LLM 生成过程的完全重放。
* 配置或运行状态的自动迁移策略。
* 跨领域分布式事务和 Tick 阶段的具体实现算法。

## 22. 设计约束总结

统一配置与规则基础设施的核心约束如下：

1. 所有子系统必须复用统一配置能力，确定性声明逻辑按需复用规则内核。
2. 运行时只使用一个运行配置版本；配置、规则或领域扩展语义的任何变化都会提升该版本。
3. 默认值、组合、覆盖和引用解析具有固定、可追查的语义。
4. 配置与运行状态严格分离，配置加载不能覆盖运行结果。
5. 领域扩展只公开最小只读视图和候选效果，不能授予直接状态写入能力。
6. 规则只使用显式输入、显式模拟时间和稳定顺序，不执行任意代码、I/O、LLM 或随机运算。
7. 相同运行配置版本和相同输入必须产生相同候选结果与追踪。
8. 共享基础设施只计算候选结果，领域系统独占不变量验证、提交和权威状态。
9. 多来源效果必须具有明确组合方式，含糊冲突和不稳定循环必须拒绝。
10. 新规则的输入、验证、编译和生效是一个原子配置更新操作，失败不改变当前配置。
11. 已开始的单次求值使用固定快照完成；已有过程保留已提交状态，后续判断使用当前有效配置。
12. Tick 只执行已经编译的确定性规则，不等待 LLM。
13. 追踪与诊断信息属于受保护的系统信息，不能绕过感知进入角色主观状态。
14. 后续感知、认知、记忆和时间系统使用共同基础设施，但继续拥有各自领域语义和状态权限。
15. 意图召回、衰减、容量裁剪和等待期限可以确定性求值，但意图形成、主观权衡和行动选择始终属于认知 Agent。
16. 主要标记、递进实体能力层级、决策模块互斥、行为树权限和 Fast Forward 零 LLM 约束必须在配置生效前完成跨领域验证。
17. 共享基础设施可以索引活动条件和目标 Tick，但不能跳过固定 Tick 或自行切换运行模式。
