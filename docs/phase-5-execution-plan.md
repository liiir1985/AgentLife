# 阶段 5 详细执行计划：主观记忆闭环

## 1. 目标、依据与阶段边界

阶段 5 在阶段 4 已有的授权感知、最小 Working Memory、Pi 认知和全局认知屏障上，完成正常实体的运行中主观记忆闭环：**获准观察或认知产物 → Working Memory → 选择性 Recent Memory → 巩固后的 Long-term Memory → 有限检索与再次使用**。玩家与 AI 各有独立记忆实例；降级实体和普通动态实体没有主观记忆。阶段退出时，AI 能依据自己曾实际处理的共同经历作出后续回应，冲突认识可以并存，未感知、未准入或已遗忘内容不能进入检索结果。

产品语义以[记忆系统设计](memory-system.md)为准，并同时遵守[感知系统设计](perception-system.md)、[认知系统设计](cognition-system.md)、[时间与整体调度系统设计](time-orchestration-system.md)及[第一版实现步骤规划](implementation-roadmap.md)。实施起点以[阶段 4 报告](phase-4-report.md)和当前代码为准：`WorkingMemoryService` 只存观察与意图、确认使用即移除；认知 Agent 只有 `submit_cognitive_decision`；感知识别未查询记忆；存档版本为 3。阶段 4 的 `restricted` 身体参与语义已按报告 §4.1 修正，阶段 5 不恢复旧的需求过滤。

本文遵守 `AGENT.md`：保持 PoC 范围，公共命名直接表达业务用途，自动测试只覆盖主要应用场景。显式保存/加载和必要步骤失败时的可见阻塞属于本阶段；**不设计自动重试、未完成记忆操作续做或异常恢复**。这一口径按用户对 `AGENT.md` 与记忆设计相关表述冲突的裁定执行。

阶段 5 不实现模拟前初始记忆候选验证与导入、配置生成 Skill、Fast Forward 完整调度及其延后队列、专用向量数据库、复杂身份合并或生物特征匹配。embedding 服务的安装、启动、模型下载与运行维护由用户自行完成，不属于本系统开发交付。玩家继续使用现有动作栏、参数向导与说话文本入口；不把阶段 4 已取消的玩家自然语言动作解释 Agent 重新纳入本阶段。

## 2. P5.0：配置、状态与内容契约

新增 `agentlife.memory` SystemSpec 和演示内容。内容包中的记忆设置声明：Working Memory 一般容量及按身体参与档位的修正、按认知块类型的离散负荷、意图预留、替换和快速衰减；Recent 时间窗口、巩固触发条件与每轮候选预算；结构/关联/语义/情境相关性、可达性、抑制、召回门槛和检索预算；身份识别门槛与修正。Embedding 提供器、模型、服务地址和表示版本属于根目录 `config/agentlife.yaml` 的系统设置，不得进入 content 包。保留阶段 4 已使用的认知容量配置，迁移其权威归属时必须保证同一配置只产生一个有效容量值。

记忆服务为每个正常实体维护 Working 条目、Recent 痕迹、Long-term 痕迹、主观实体档案、识别关联、来源关系、可达性与抑制状态。痕迹至少记录所属角色、来源类别与标识、形成 Tick、主观文本、关联的观察者本地引用和状态版本。索引与向量是从有效痕迹生成的派生数据；审计归档与活动索引隔离，不作为检索或感知识别来源。认知意图仍由 `CognitionService` 持有，Working Memory 只持有其激活引用。

配置验证拒绝没有正常实体记忆设置、无效容量或时间窗口、无界候选/工具预算、缺失语义提供器版本、跨领域非法引用，以及允许感知投影直接读取 Identity、控制来源、其他角色记忆或管理数据的配置。PoC 只维护一套当前语义表示；版本不匹配时明确拒绝加载或使用，不做索引迁移。

**交付与验收：**演示内容包能加载并形成稳定配置身份；两个正常实体得到隔离的空记忆实例，降级实体没有实例；相同配置、状态和 Tick 得到相同容量与检索门槛结果。

## 3. P5.1：Working Memory 生命周期

扩展现有 `WorkingMemoryService`，使观察、已提交的认知产物、检索激活引用和意图引用各有明确类型、来源、负荷、进入/最近使用 Tick 与保持状态。观察和认知产物只有经来源、角色和版本验证并成功准入后，才能进入认知或成为编码候选。当前认知决定产生的理解、反思或判断必须先作为带来源的新认知块准入，不能从决定文本直接写成 Recent 痕迹。

容量不足时按配置化优先级确定性替换；容量下降在下一个稳定边界收缩，恢复容量不自动找回已删除内容。意图引用只占其预留部分，不复制或延长意图本体。未使用内容按模拟 Tick 快速衰减并真实删除；已编码或检索激活的条目退出 Working Memory 时只移除激活引用，不删除仍有效的持久痕迹。

**关键流程调整：**阶段 4 的 `confirmUsage` 会立即删除条目。阶段 5 将其拆成“确认实际使用 → 在本轮固定来源集上验证消费、编码和强化 → 完成记忆提交 → 按保持/衰减规则释放条目”。确认仅命名当前轮次获准条目；仅被模型看到、检索命中或自动确认事件送达，都不等于认知实际使用。玩家决定入口按其实际选择或表达交接可验证的使用来源，不允许为了形成记忆而批量确认全部观察。

**交付与验收：**同一容量和输入得到相同准入/替换结果；未使用条目随模拟时间删除；已编码条目离开 Working 后仍可按合法线索检索；未准入条目无法编码。

## 4. P5.2：Recent Memory 选择性编码与遗忘

认知决定增加明确的编码候选，引用本轮实际使用且仍可核验的 Working 条目。候选可以表达已获准观察、角色确已形成的理解或新反思，并保留第一手观察、听闻、推测等来源类别。记忆服务检查角色归属、来源版本、实际消费、内容权限和同一经历的重复编码，再原子建立 Recent 痕迹、有效来源、结构关联及语义表示。单纯检索旧痕迹不生成新 Recent；对旧痕迹形成的新反思可作为独立认知块编码，并与来源痕迹建立关联。

Recent 不设置容量上限，按配置的模拟时间窗口到期。到期且未巩固的痕迹从活动状态、结构/关联/语义索引和实体档案支持中一起移除；受保护审计记录仅用于管理诊断。删除后的内容不能因强线索、模型工具或档案查询重新进入角色上下文。

**交付与验收：**共同经历只有在认知实际使用并选择编码后才成为 Recent；未编码内容到期不留下隐含痕迹；已删除痕迹和仅由其支持的断言均不可检索。

## 5. P5.3：Long-term Memory 巩固与主观实体档案

在普通模式稳定边界，根据明确的模拟时间、窗口临近或已配置身体状态触发巩固，不硬编码“必须睡眠”。先固定当前角色的有限 Recent 候选及来源，再由独立、受限的记忆 Agent 判断保留与归纳；它只接收候选，不能读取完整库、世界 Ground Truth、其他角色记忆或审计归档。模型输出是候选，须经记忆服务验证后才提交。单条痕迹可迁移为 Long-term；多条可形成一个带来源关系的长期结果。成功后移除相应活动 Recent 副本；巩固允许概括、偏差和信息损失，但不能把未获准信息伪装为亲历。

主观实体档案是有效 Recent/Long-term 痕迹支持的物化视图，覆盖人物、物品、地点等允许识别的实体。名称、类别、属性、印象和关系断言由认知明确提交，记忆服务验证其 Working 来源及支持痕迹；听见自我介绍不会自动成为可信名称。冲突断言可以并存，首选称呼和主观确信按配置化规则确定；来源删除或巩固时重新计算支持，失去全部支持的断言失效。档案不修改人物 Identity，也不能覆盖当前感知描述。

**交付与验收：**单条迁移和多条归纳均可在演示中发生；来源移除后不产生 Recent/Long-term 双份活动副本；两个角色能对同一实体保持不同、甚至互相冲突的称呼或关系判断。

## 6. P5.4：受限混合检索与认知接入

为认知 Agent 增加 `memory_search` 工具。一次 Cognition Round 固定角色、Tick、配置/状态版本、可用 Working 上下文和查询预算；Agent 可在预算内提交或调整 Retrieval Intent，但只能使用自然语言线索、观察者本地档案引用、已授权的时间/地点/主题/类型等条件，不能传世界实体 ID 或跨角色私有引用。查询服务先按角色归属、活动状态和来源权限过滤，再稳定合并结构索引、有限关联图、语义表示和当前情境候选。

查询相关性与痕迹可达性分别计算，再结合抑制形成综合激活。语义相似度有配置上限，不能越过角色、删除状态或召回门槛。只有过门槛的有限候选可交给记忆 Agent 受限重排；重排输出再按候选身份与来源验证，形成 Activation Set。检索命中不等于想起：结果还需参加 Working Memory 一般容量准入，认知 Agent 只读取成功准入的带来源片段，并在**同一次认知调用**内解释片段、权衡意图和提交行动决定。仅决定实际引用且成功提交的片段获得强化；临时解释不自动成为新记忆。

现有意图候选保持独立命名空间和预留容量，可复用相关性与可达性计算，但检索排序不能替角色选定应追随的意图。认知工具仅用于查询与提交候选，不得获得文件、数据库、完整世界读取或直接记忆写入能力。

**交付与验收：**结构与语义线索能召回同一角色仍有效的有限经历；高可达但无关内容不自动进入结果；低可达但高度相关的长期内容仍有机会激活；记忆 Agent 不能扩展候选集或编造来源。

## 7. P5.5：本地 embedding HTTP 适配

定义可替换的 `EmbeddingProvider`，分别对痕迹和查询文本生成向量。默认实现调用本地 Ollama 的 `POST /api/embed`；根目录 `config/agentlife.yaml` 选择提供器、模型、服务地址和表示版本，演示系统设置示例使用 `http://localhost:11434/api/embed` 与 `embeddinggemma`。适配器核对响应向量数量、维度及有限数值，记录提供器/模型/表示版本；同一检索只比较同一表示版本的向量，在进程内计算余弦相似度。演示和普通测试使用确定性假提供器，不依赖安装 Ollama 或网络。

用户提供已运行且已加载所选模型的 embedding HTTP 服务后，人工验收只检查系统配置能连接该地址、`/api/embed` 能为中文演示线索返回向量，以及阶段 5 的真实服务检索流程能够完成。服务安装、启动、模型下载和运行维护均不写入开发任务或验收责任；请求与响应形状以[Ollama 官方 embedding API 文档](https://docs.ollama.com/api/embed)为准。

必要的编码或查询发生时，提供器失败应使当前记忆处理返回可见错误并阻塞 Tick；未触发语义工作的 Tick 不主动调用服务。错误不改变痕迹内容或状态，也不解释为角色遗忘。PoC 不提供自动重试、后台索引迁移或故障切换。

## 8. P5.6：主观身份关联回接感知

感知仍先依据当前世界/身体材料形成分辨率和外在描述。只有当前分辨率达到可尝试辨认的条件，才向记忆服务提交观察者、不透明实体锚点、分辨率、连续观察、辨认修正及依赖版本。记忆服务依据该观察者的有效档案支持、识别关联强度和可达性确定性计算置信度；锚点本身不贡献分数。

低于阈值只显示当前分辨率允许的模糊描述。达到阈值只向感知返回观察者本地档案引用、首选称呼、数值置信度及自然语言等级；共同经历、关系和完整档案仍走 `memory_search`。阶段 4 内容投影里可辨认时直接使用的称呼不得继续作为无记忆观察者的身份捷径；当前衣着和姿态继续来自当下感知。关联衰减后可以认不出仍有档案的实体；重新关联须由认知引用当前观察与旧记忆提出候选，并由记忆服务验证。

**交付与验收：**首次见面不会从实体 ID 或人物配置获得真实姓名；听到名字并选择性形成有来源的认识后，未来在足够清晰条件下可以主观认出；低分辨率或低置信度不附带档案。

## 9. P5.7：稳定边界、存档、界面与演示

调整 Runner 与 CognitionCoordinator 的交接顺序：世界/身体/感知提交 → 最小身份查询 → Working 观察与意图准入 → 当前轮次内的受限记忆查询和回忆准入 → AI 或玩家决定 → 验证并提交认知及意图变化、统一交接身体计划供 Body 验证 → 确认实际消费、Recent 编码、强化和档案断言 → 到期巩固 → 意图与 Working 衰减 → Recent 到期删除 → 原子发布 Tick。模型或玩家等待期间模拟时间冻结，必要记忆步骤完成前不发布新 Tick；同轮模型返回顺序不改变计划顺序或记忆提交顺序。任何失败只公开错误和阻塞状态，不半发布角色记忆。

显式存档从版本 3 升到版本 4，保存每个正常实体的权威记忆状态、档案支持、可达性、表示版本和当前稳定边界；加载核对存档配置身份和语义版本，明确拒绝版本 3，不承诺自动迁移。索引可以从有效痕迹重建，但加载后的首个查询必须得到与保存前相同的授权结果。管理监视面板展示层数、数量、索引/提供器状态、最近错误及角色归属；普通 TUI 仍只展示玩家获得的授权观察和认知可用内容，不显示完整私密文本或诊断。

增加阶段 5 演示入口、`phase5:verify` 与 `phase5:demo` 脚本，并在完成实现时提交阶段报告。演示沿用现有地点、人物和动作机制，只补充一次可选择性编码、保存后可用线索回忆的共同经历；具体地点或人物不硬编码在记忆服务中。

## 10. 关键接口交接

| 边界 | 输入与输出 | 权威与限制 |
| --- | --- | --- |
| 感知 → 记忆 | 观察者、锚点、当前辨认条件 → 最小身份结果 | 感知不读取完整档案；记忆不读取世界真相 |
| 记忆 → 认知 | 已准入 Working 条目和带来源回忆片段 | 未准入、已删除及审计内容不进入 CognitionInput |
| 认知 → 记忆 | 实际消费、编码、档案断言、识别重连候选 | 记忆服务验证并提交；模型只提出候选 |
| 认知工具 → 检索 | 有预算的 Retrieval Intent → 有限已准入片段 | `memory_search` 不暴露完整库或其他角色私有状态 |
| 记忆 → 巩固 Agent | 固定的有限 Recent 候选 → 长期结果候选 | Agent 不直接写状态，不访问候选以外内容 |
| 记忆 → embedding | 有效痕迹或查询文本 → 带表示版本的向量 | 同版本比较；提供器错误可见并阻塞必要处理 |
| Runner → 存档 | 稳定边界的各角色记忆状态 → 版本 4 快照 | 只做显式保存/加载，不做异常续做 |

公共 API 和类型名称须通过 `AGENT.md` 第 3 条检查：读者不用先理解底层索引或框架，就能区分“记忆查询、编码、巩固、辨认、使用确认”等业务操作。内部算法可以使用技术术语，不能让技术术语替代公共业务含义。

## 11. 实施顺序与最小验收

按 P5.0 → P5.1 → P5.2 → P5.3 → P5.5 → P5.4 → P5.6 → P5.7 实施：先固定状态与来源，再建立持久痕迹和巩固；embedding 适配就绪后完成语义检索，最后将身份关联与稳定边界接入全流程。每一工作包提交前执行 TypeScript 检查及相关阶段回归；不为每个字段、异常组合或实现分支另写测试。

自动测试仅覆盖以下主要跨系统场景：

1. 观察或认知产物经 Working Memory 准入、实际使用及明确编码后成为 Recent；未准入或未使用内容不编码。
2. Working 未编码内容快速删除；Recent 到期删除；单条与多条巩固后仍可回忆且无活动层双份副本。
3. 两个正常实体对同一实体持有不同且可冲突的认识；降级实体没有记忆实例；首次见面和低置信度不泄露身份。
4. 结构、关联和语义线索只召回同一角色仍有效且超过门槛的有限候选；删除或审计内容无法重新进入结果。
5. 显式保存、加载后继续同一回忆流程；必要记忆处理或模型等待期间 Tick 不推进，失败可见且不半发布。

端到端 faux 场景：**相遇并交谈 → AI 实际使用一条共同经历 → 选择性编码 → 巩固 → 保存与加载 → 后续线索触发有限回忆 → AI 的回应经过 Body/World 执行**。用户提供服务后再做真实 embedding 接口的人工冒烟；真实服务和真实认知模型不进入普通 CI。阶段退出报告记录验证命令、演示摘要、接口人工验收结果、已知限制及与领域设计的偏差。
