# 阶段 3 详细执行计划：上下文动作 TUI 竖切

## 1. 目标与边界

阶段 3 提供无 LLM 的可玩终端界面。底部常驻区域显示当前上下文存在候选对象的内容动作；左右键选择，Enter 进入参数向导，空格切换普通连续运行和暂停，`/` 打开管理命令输入。动作填写完成后只排入下一 Tick，不隐式推进时间。

本阶段不实现感知、认知、记忆、自然语言解释、LLM 或 Fast Forward。普通界面使用受限的临时玩家展示投影，不把它宣称为角色感知；阶段 4 再切换为正式授权观察。

本文服从 `AGENT.md`：保持 PoC 范围，只验证主要场景，公共命名必须能从业务用途直接理解。

## 2. P3.0：内容定义的动作命令

新增 `agentlife.interaction/action-command`，声明动作名称、说明、顺序、别名、Body 动作引用、冲突策略和有序参数。

参数分为：

- Entity 参数：绑定 `target` 或 `destination`，候选范围为当前出口、同地点物品、持有物或同地点实体，并可按内容属性过滤。
- 文本参数：声明字段、提示和长度范围；文本只作为不透明动作输入保存，不直接改写世界或身体。

发布必须拒绝重复命令词、管理命令冲突、错误动作或属性引用、重复绑定和无效文本长度。交互配置参与 `configId`。

演示内容提供移动、拿取、放置、操作、挥手和说话。拿取要求 `portable=true`，放置目标要求 `support=true`，操作要求 `operable=true`。这些名称属于演示内容，不进入 TUI 硬编码。

## 3. P3.1：玩家展示和上下文动作

`PlayerView` 只返回玩家当前地点、出口、同地点公开实体、持有物、玩家动作和普通运行摘要。远处实体、控制来源、主要标记、其他角色身体指标、行为树和完整客观事件不得进入普通视图。

动作栏不预测或试运行裁定。它只查询当前稳定状态：

- 角色是否运行；
- 当前身体模式是否拥有动作能力；
- 必需 Entity 参数是否存在满足位置、关系和内容属性的候选。

查询不得调用规则引擎、创建临时权威状态、占用资源、生成事件或改变版本。正式计划仍在 Tick 中由 BodyService 和 WorldService 权威验证。

空房间不显示拿取；无出口不显示移动；没有持有物或支撑物不显示放置；没有可操作物不显示操作。

## 4. P3.2：运行控制

`SimulationController` 拥有 Runner、待接纳计划、单一定时器、RuntimeStore 和玩家身份。

- 完成参数向导只排队。
- `/step` 执行一个完整 Tick。
- `/run` 每秒重复完整 Tick；`/run <ticks>` 支持限步。
- 空格在动作栏焦点下切换运行与暂停。
- 屏障、失败、静止或达到限步自动停止。
- 连续运行中确认动作时先在最近稳定边界暂停，再重新查询动作。
- 任意时刻最多一个定时器和一个 Tick；现实计时不进入领域求值。

保存只允许稳定 Tick 且没有待接纳计划时进行。加载停止连续运行、清空待接纳计划、核对配置与 System 版本，并建立新时间线。

## 5. P3.3：终端交互

宽屏显示顶栏、地点、实体、滚动日志和固定动作栏。窄屏使用地点、实体、日志三个标签页，动作栏始终固定。120 列为布局分界。

动作栏按内容顺序展示可用动作：左右循环选择，Enter 确认，空格运行或暂停。没有动作时显示明确静止文本。

参数按内容顺序逐项处理：Entity 使用 `SelectList`，上下选择、Enter 确认；文本使用 `Input`，支持中文与粘贴。Esc 返回上一项，第一项时取消。最终提交前重新确认动作和对象仍存在，但不预测裁定结果。

动作栏按 `/` 打开管理输入，支持 `/step`、`/run`、`/pause`、`/save`、`/load`、`/status`、`/monitor` 和 `/help`。空格只在动作栏焦点切换运行；在文本和管理输入中保持普通字符语义。

F2 与 `/monitor` 打开管理员视图，显示 Entities、World、Scheduler、Memory 未接入占位和 Diagnostics。管理员数据不得回流普通投影或参数候选。

## 6. 实施顺序

1. 注册交互 SystemSpec、内容类型和演示命令。
2. 扩展 ActionStep 与存档载荷以保存文本输入。
3. 实现玩家展示投影、Entity 候选和上下文动作查询。
4. 实现 SimulationController、单步、连续、暂停和保存加载。
5. 收敛正式 TUI、动作栏、参数向导、管理输入和监视面板。
6. 增加脚本演示、主要路径测试和阶段报告。

## 7. 测试与退出条件

自动测试覆盖：内容验证、空上下文隐藏动作、属性候选、查询无副作用、Entity/文本参数、动作只排队、单定时器、空格切换、普通/管理隔离和宽窄布局主要路径。

验收命令：

```text
pnpm phase2:verify
pnpm phase3:verify
pnpm phase3:demo
pnpm phase3:demo
```

两次演示及原存档继续/加载后继续的领域摘要必须一致。Windows Terminal 人工验收左右选择、空格切换、Entity 选择、中文输入、`/` 管理入口、窗口缩放、F2 和 Ctrl+C 恢复。

阶段完成要求：内容可新增动作而无需修改 TUI；普通视图不泄露管理状态；单步和连续运行共享同一 Tick；保存加载可继续确定性结果；阶段 0–2 回归保持通过。
