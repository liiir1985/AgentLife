# 阶段 4 报告：授权感知、指令式玩家交互与 Pi 认知

- 日期：2026-09-22
- 范围：感知与认知配置契约、正式感知链路、可观察说话动作、授权玩家视图、最小 Working Memory、认知状态与意图、全局认知屏障、Pi AI 认知、TUI 状态与监视面板、存档版本 3 与屏障保存
- 结论：阶段 4 的主要业务路径已经实现并验证。玩家只看到自身角色的授权观察；AI 只依据准入的观察与自身意图作出决定；玩家与 AI 的计划经过同一个 Body 与 World 验证；等待模型或玩家期间模拟时间冻结；同轮计划按稳定顺序统一交接。

## 1. 交付内容

### 1.1 配置与内容契约（P4.0）

- `agentlife.perception@1.0.0`：分辨率等级、实体外在表现、事件表现、感官通道与感知设置。
- `agentlife.cognition@1.0.0`：认知容量、计划长度、模型尝试与超时、空闲等待边界、provider/model 与允许动作，以及认知提示。
- 演示内容：三个分辨率等级、六个实体外在表现、视觉/听觉通道、说话事件表现、感知设置、认知设置与提示、听觉身体通道。
- `agentlife.body@1.2.0` 动作新增 `utterance` 声明：动作完成时把哪个输入字段的内容变成可听见的事件。
- `agentlife.character@1.2.0` 要求正常实体关联 perception、cognition、memory 三个模块。
- 配置验证拒绝：感知投影引用 Identity、控制来源、认知或记忆；低分辨率投影暴露身份；同一实体重复声明外在表现；通道不承载事件却声明事件表现；认知设置越过计划长度或空闲等待边界；认知设置声明后没有提示。

### 1.2 感知链路（P4.1、P4.2）

- `WorldService.perceptionMaterial`：当前地点、出口、同地点人物与物品、持有物、环境值、本 Tick 变化的环境成员与本 Tick 事件，全部是用途受限材料，人物与物品只带内容声明的外在表现。
- `BodyService.perceptionMaterial`：各感官通道的可用性与效率，以及本 Tick 该身体自己能感觉到的动作结果。
- `PerceptionService`：按通道检查可达性与条件（光照、雾气、通道效率），计算分辨率等级并选择对应投影，生成出现、持续、变化、消失、重新出现、事件与自身结果观察，维护观察者局部引用、连续观察、重复抑制、已处理材料版本、注意输入版本与待处理观察流。
- 连续观察以本轮材料为准：材料里仍然存在的对象即使当前读不到也保持连续，离开的地点与不再相邻的出口会结束连续并形成消失观察；玩家的可用出口因此始终等于当前地点声明的出口。
- 说话事件：只有动作走完全部阶段后，World 才记录可听见的 `utterance` 事件；未完成、被拒绝或被中断的说话不产生事件；同地点角色才能在听觉条件下收到，说话者本人听到的是自己的话。

### 1.3 玩家授权视图与指令（P4.3）

- `PerceivedPlayerView` 取代阶段 3 的临时投影：地点、出口、人物与物品一律来自玩家自己的观察，未识别对象按当前分辨率描述。
- 动作候选只从授权观察筛选（出口、可见物品、持有物、可见实体），属性过滤仍只用于发现候选。
- 观察者局部引用在参数确认时映射回受保护锚点，计划使用 `source: player-command`。

### 1.4 最小 Working Memory 与认知状态（P4.4）

- `WorkingMemoryService`：只准入观察与意图，容量由内容声明，超限按显著度、时间与稳定身份确定性裁剪；确认使用的条目被释放，未准入的确认不会释放任何东西。
- `CognitionService`：注意、主观理解、疑问、持续性决定、多条意图（新建、重申、暂停、满足、放弃、使用强化）与空闲契约。
- 空闲契约必须有限且有可验证起因：外部事件、确定重审时刻或持续活动，并受全局等待上限约束。

### 1.5 认知需求与全局屏障（P4.5）

- 第 8–12 阶段成为真实状态机：感知、认知需求、屏障、消费确认与意图维护、发布。
- 认知需求来源：尚未形成决定、听到可回应的发言、自身动作结果、达到变化显著度的新观察、空闲重审时刻与等待上限到期；身体 `forbidden` 完全不参与认知，`restricted` 只回应事件与结果。
- 屏障固定时间线、Tick、配置版本、客观状态版本、参与者、授权观察、准入结果与已交接计划；等待期间世界冻结，不能开始下一个 Tick。
- 轮次解决后按实体与计划身份稳定排序，统一交给 BodyService 验证，再发布完整 Tick。

### 1.6 Pi AI 认知（P4.6）

- `PiCognitionAgent`：通过 Pi provider factory 选择 provider/model，注册唯一工具 `submit_cognitive_decision`，对原始工具参数严格校验，请求身份为 `timelineId + roundId + requestId`。
- 迟到响应只能进入诊断：被取代或超时的请求不得提交决定；没有合法提交时按上限重试，重试失败则屏障失败并停止 Tick。
- AI 表达转换为说话的 ActionStep，必须经 Body 执行后才成为可听见的事件。

### 1.7 存档与加载（P4.8）

- 存档 schema 升级到版本 3，携带感知、最小 Working Memory、认知状态、意图、空闲契约与认知轮次；版本 2 存档明确拒绝而不迁移。
- 屏障期间的保存请求进入 pending，在当前 Tick 完整发布后、下一 Tick 开始前执行；已有 pending 时再请求会被拒绝；加载取消活动请求、清除 pending 保存并建立新时间线。

### 1.8 TUI 与演示

- 顶栏区分等待 AI、等待玩家选择、计划统一交接中、保存待处理与认知失败；空格不能绕过屏障；`/skip` 用于本轮不提交计划；普通日志只显示玩家自己的观察，按观察身份去重。
- 管理面板扩展为 Perception、Cognition、Working Memory（只显示容量与数量）与 Diagnostics。
- `pnpm phase4:demo` 用 faux 模型走完整剧情；`pnpm phase4:tui` 支持 `--provider/--model` 的真实模型人工验收。

## 2. 关键语义

- **观察只来自材料**：感知服务不遍历世界，也不按锚点解引用实体；材料之外的事实无法进入观察。
- **信息不升级**：条件不足时分辨率下降，投影的粗化路径由内容声明，低分辨率不能表达身份。
- **观察而非信号**：认知读到的是结构化观察的文本渲染与观察者局部引用，没有亮度、距离等原始数值。
- **身份不属于感知**：第一阶段不实现身份关联；观察中的称呼来自内容为外在表现声明的投影，人物配置中的姓名、身世与控制来源永不进入观察。
- **命中不等于想起**：观察先进入待处理流，再由 Working Memory 准入；只有认知确认实际使用的观察才被释放与强化。
- **同轮无优先级**：模型返回顺序、玩家是否先于 AI 提交都不影响交接顺序；计划一律按实体与计划身份排序后交给 Body。
- **冻结即不推进**：屏障期间时间、Tick、确定性过程、玩家选择界面全部停在固定快照上。
- **失败不半发布**：屏障失败时 Tick 不发布，客观状态保持在屏障前的位置，只公布失败原因。

## 4. 已知限制与偏差

- **身份关联后移到阶段 5**：感知只给出内容声明的称呼，不查询记忆，也不产生识别置信度。
- **恢复上下文未实现**：认知中断恢复的一次性感知交接属于后续阶段。
- **环境观察合并进地点观察**：环境值变化并入地点观察的文本，不生成逐事实观察。
- **注意只用于重发**：认知写入的注意用于让被关注对象在注意变化时重新形成观察，不实现完整的注意筛选与通道负荷。
- **Working Memory 无时间衰减**：快速衰减、Recent/Long-term 编码与巩固属于阶段 5。
- **玩家没有输入解释模型**：玩家通过动作栏与参数向导提交结构化指令；自然语言意图推断不在阶段 4。
- **距离、遮挡与跨地点声音未实现**：只判断是否同地点。
- **受限身体不做空闲重审**：身体把认知标为 `restricted` 时只回应事件与动作结果，不主动按重审时刻唤醒（演示中醒着程度下降时即为此状态）。
- **PTY 冒烟的覆盖范围**：真实终端冒烟覆盖启动、渲染、运行与暂停、参数向导、监视面板、保存与退出；屏障期间“空格不能绕过”的等待行为由 `tests/phase3-tui.test.ts` 的终端级用例确定性覆盖，不在人工冒烟里复现。
- **普通界面仍携带受保护锚点**：界面显示只使用观察文本与局部引用，锚点仅用于把选择映射回受保护对象，界面没有任何按锚点查询的能力。
- **阶段 3 演示入口被取代**：`src/tui/phase3-app.ts` 与 `src/interaction/phase3-demo.ts` 已删除，由 `phase4:tui` 与 `phase4:demo` 取代（旧入口无法在没有模型端口时运行含 AI 角色的时间线）。

## 5. 下一阶段边界

- 感知与认知的稳定边界顺序、屏障语义、计划批量交接与存档版本升级方式保持为本阶段确立的约定。
