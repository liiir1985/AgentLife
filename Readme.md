# AI伙伴角色实验系统设计

## 1. 项目目标

构建一个具有持续生活、独立行为和个人经历的 AI 伙伴，使用户能够通过自然聊天与共同活动，逐渐形成独特的伙伴关系。

系统不以任务执行或剧情推进为中心，而是通过角色认知、身体行动、世界反馈与记忆演化，形成持续的个人经历和共同经历。

交互形式为纯文本，世界观为虚构世界，聊天与共同活动并重。

## 2. 总体架构

运行时系统由统一配置与规则基础设施、世界、角色、身体、认知、记忆和时间调度组成；设计时由配置生成 Skill 将世界观与角色设计文档转换为运行所需配置。

每个角色是独立实例，拥有自己的身份、身体、认知状态、记忆及生命周期。

基本运行闭环：

**世界与身体更新 → 角色感知 → 认知决策 → 产生意图 → 身体执行 → 世界反馈 → 形成经历**

世界与身体持续运行，LLM 按需参与认知，不直接控制世界状态。

## 3. 统一配置与规则基础设施（Configuration & Rule Infrastructure）

统一配置与规则基础设施为各运行时子系统提供共同的配置和声明式规则能力，避免世界、人物、身体及后续子系统分别实现结构相似但互不兼容的解析器、验证器和规则引擎。

配置基础能力包括类型与结构约束、默认值、组合与覆盖、引用解析、命名空间、版本标识及统一验证。人物配置可以引用身体模板，身体模板可以组合器官、能力、指标和效果映射，具体子系统不需要重复实现这些通用机制。

规则基础能力包括受限条件、触发器、效果映射、持续过程、依赖关系、组合运算、编译、索引和确定性求值。阈值、分段常量、分段线性及未来增加的通用规则表达应在共享基础设施中实现一次，并供有需要的子系统复用。

各子系统仍然拥有自己的领域语义和权威状态。世界、人物、身体、感知、认知或记忆系统分别注册自己允许读取的视图、条件词汇、效果类型和领域验证；统一基础设施只对声明进行解析、验证和求值，不能绕过子系统接口直接修改其权威状态。

共享能力通过版本化的通用内核和领域扩展逐步增强。新增运算、映射或调试能力应优先扩展基础设施并保持现有配置语义兼容，而不是在单个子系统中创建另一套近似机制。

规则运行必须确定、可追查且不执行任意代码。LLM 或配置生成 Skill 可以生成候选配置与规则，但只有通过共享结构验证和对应子系统领域验证后才能加载；运行时 Tick 不调用 LLM 来解释已经加载的规则。

该子系统的详细设计见[统一配置与规则基础设施设计](docs/configuration-rule-infrastructure.md)。详细设计确立“配置能力必须复用、规则能力按需复用”、单一运行配置版本、配置更新原子生效以及确定性求值内核不使用随机运算或 I/O 等原则。

## 4. 世界系统（World）

世界分为静态设定与动态状态。

静态设定包含世界观、环境氛围、基础规律、地点及物品类型。

动态状态包含角色位置、物品状态、环境变化及正在发生的事件。

角色与动态物品拥有独立的更新生命周期，共享统一的世界时间。

世界负责实际行动结果、状态一致性及客观事件记录。

支持开放式行动意图，不要求每一种自然生活行为都具有独立的硬编码动作接口。

简单行动可以根据通用规则执行；具有不确定结果的行动需要独立的环境反馈。

角色不能通过语言叙述直接修改世界事实。

## 5. 角色系统（Character）

每个角色包含：

* **Identity：** 身世、个人历史、人格、偏好、自我认识。
* **Body：** 身体能力、器官、资源占用及行动状态。
* **Perception：** 通过身体感官获取有限的世界信息。
* **Cognition：** 维持当前认知状态，形成和调整意图。
* **Memory：** 保存角色视角下形成的记忆和经验。
* **Continuity：** 保存未结束的意图、活动及持续性决定。

角色具有认识用户之前的个人历史，但与用户的共同经历必须通过实际互动形成。

角色只能通过感知、记忆和外部信息了解世界，不能直接读取完整世界状态或其他角色的内部状态。

## 6. 身体与行动系统（Body）

LLM 负责形成意图，身体负责执行。

初期身体能力包括说话、行走、手势、拿取、放置和简单物品操作。

行动根据器官占用、身体能力、环境条件及资源限制进行执行。

兼容行动可以并行，存在资源冲突的行动不能同时执行。

行动具有开始、进行中、完成、中断和失败等状态，可以持续多个 Tick。

身体系统自行推进能够确定执行的动作，无需每个 Tick 调用 LLM。

身体与认知独立运行。角色没有进行认知处理时，身体仍持续存在、推进既有动作和身体过程，并能够受到其他角色及环境的影响。

身体通过可配置指标及效果映射表达体力、身体完整度、唤醒能力等状态。指标可以使用阈值、分段常量或分段线性方式影响能力、资源、感官效率及认知参与许可；具体指标、区段、曲线、消耗和恢复规律由世界及身体模板配置决定，不由引擎硬编码。

身体状态可以限制或禁止认知参与，但身体变化不代表角色已经感知、理解或记住相关事件。

行动结果通过感知系统反馈给角色认知。

## 7. 认知系统（Cognition）

认知是持续存在的状态，而不是每次调用 LLM 时重新生成的完整角色状态。

认知系统维护当前注意力、主观理解、疑问、行动意图、持续性决定及认知连续性。当前认知状态只保存下一次认知需要延续的最小内容；其中的理解、疑问和理由可以是自然语言，结构只用于明确类型、来源和生命周期。

不要求所有行为都具有明确的 Goal。

角色可以直接形成即时意图，也可以形成需要长期维持的目标或承诺。

长期决定具有持续性，不因注意力转移或新一轮 LLM 调用而自动失效。

已经接受的共同约定应能够影响后续实际行动，同时允许角色根据新情况调整或取消决定。

认知与身体执行职责独立：没有新决策需求时，身体和世界自行推进已有动作；出现需要角色反应或选择的稳定边界时，模拟暂停并完成认知决定，然后再继续推进。

AI 角色的一次认知 LLM 调用同时形成必要的认知状态更新、表达内容和短身体计划，不固定增加第二次 LLM Pass。认知决定经过格式、来源和权限验证后提交；身体计划仍由身体系统独立验证和执行。

模型实际返回的原始响应及其结构化决策追踪可以作为受保护诊断保存，但不属于角色认知或记忆，不能自动回灌为后续角色知识。系统不要求或伪造供应商没有返回的隐藏推理过程。

### 7.1 自主意图的形成

自主意图可以来自：

* 身体状态与内部需求。
* 稳定偏好与个人历史。
* 当前感知到的环境机会。
* 已有意图、持续性决定及共同约定。
* 过去经历形成的兴趣、疑问与经验。

角色不必因身体空闲而立即产生新意图。

允许休息、等待、观察和不采取新行动。

经历可以改变角色未来的关注、偏好和行动选择，但不要求每次行动都形成新目标。

## 8. 认知调度

系统采用离散模拟，模型调用和用户等待消耗的现实时间不计入模拟时间。世界与身体的确定性 Tick 不调用 LLM，但一次完整模拟轮次可以在 Tick 产生感知和认知需求后进入认知阶段。

当当前稳定时间点存在必须解决的认知需求时，整体调度建立全局认知屏障。在所有必要 AI 角色完成认知决定、所有必要用户角色输入或跳过之前，不开始下一个世界或身体 Tick。

认知调用由以下条件触发：

* 出现需要理解或回应的新感知。
* 当前行动完成、失败、中断或需要新的决策。
* 既有决定的条件发生变化。
* 内部状态产生值得关注的变化。
* 已接受决定登记的明确模拟时间或其他可确定关注条件到达。

多个 AI 角色的 LLM 调用可以在现实计算层并发执行，但它们读取同一模拟快照，不能看到其他角色本轮尚未提交的决定。模型返回顺序不产生模拟优先级；全部必要参与者完成后，本轮身体计划才统一交给身体系统。

系统不设置固定周期思考，也不允许没有明确承诺或外部条件的自由认知预约。身体动作完成不必自动触发完整认知；身体空闲、Tick 推进和现实时间流逝都不构成唤醒理由。

动作执行期间默认保持认知静默。新对话、高显著刺激、动作结果、前提变化或明确决策点可以在合法稳定边界建立认知屏障。认知决定本身不自动停止当前动作；新动作继续通过并行、排队或替换策略接受身体系统验证。

身体侧有限动作阶段可以使用工作量与有效执行速率确定性推进；瞬时、持续保持和等待外部条件的阶段使用各自明确完成条件。认知系统只消费阶段结果，不计算动作工期。

用户角色到达需要认知判断的边界时，用户本人替代自主认知 LLM。模拟暂停等待用户输入或明确跳过；用户自然语言意图由输入解释 LLM 转换为与 AI 角色相同语义的表达和身体计划，并接受相同的身体能力、资源及世界规则。跳过本轮不取消已有动作或长期事项。

该子系统的详细设计见[认知系统与认知调度设计](docs/cognition-system.md)。

## 9. 记忆系统（Memory）

记忆系统模拟有限感知、选择性编码、信息遗失和主观回忆，而非将完整客观历史直接提供给角色。

### 9.1 Ground Truth

世界独立保存完整客观事件，包括实际行动、对话和状态变化。

Ground Truth 不属于角色记忆，不能在普通认知与记忆检索中被直接读取。

角色可以通过实际感知、外部记录或其他角色提供的信息重新获得过去的事实。

### 9.2 Working Memory

维护当前认知直接可用的有限信息。

内容受到注意力、认知负荷、当前情境及个人偏好的影响。

不等同于完整 LLM Context。

### 9.3 Recent Memory

保存角色近期实际感知并编码的经历。

允许信息遗漏、细节不完整及尚未确定的主观解释。

不直接复制完整世界事件。

### 9.4 Long-term Memory

通过选择性巩固形成长期情景记忆、知识、经验及关系记忆。

保留角色自己关注的内容及其主观理解，不要求完整、准确地复现客观历史。

不同角色对同一事件可以形成不同的记忆。

记忆的重要性允许根据后续经历重新评估。

近期记忆与长期记忆可以共享底层结构，通过巩固和激活状态区分。

### 9.5 Memory Reconstruction

记忆检索返回的是基于记忆痕迹重建的主观回忆，而非直接查询客观事件。

回忆可能存在细节缺失、模糊、混淆或不确定性。

重建结果可以影响当前认知，但不能自动作为新的独立证据覆盖原始记忆痕迹。

通过后续实际感知获得的新证据，可以修正角色对过去的认识。

## 10. 记忆与认知的交互

记忆在认知决策之前激活，而非仅用于生成对话。

基本流程：

**当前感知与认知状态 → 相关记忆激活 → 主观回忆重建 → LLM 认知决策 → 行动与反馈 → 新经历形成**

记忆激活由当前感知、注意力、意图及既有记忆关联共同决定。

部分激活记忆可以跨认知周期保留，并随着注意力转移退出当前认知状态。

长期记忆不需要在每次认知周期完整加载。

新经历的记录、记忆巩固和长期偏好变化不必与每次认知调用同步发生。

## 11. 时间与生命周期

使用统一模拟时钟推进世界。

角色和动态物品拥有独立的 Update 逻辑，但不独立推进世界时间。

初期支持手动 Tick、连续推进、暂停及状态检查。

模拟时间不与现实时间强制绑定。

World Tick 负责推进身体、物品和环境状态；稳定阶段产生认知需求时，整体调度建立全局认知屏障，等待 AI 决定以及用户输入或跳过。所有必要参与者解决后才进入下一 Tick。记忆巩固可以独立调度，但不能绕过整体模拟时间边界。

不要求每个 Tick 都产生新事件、新目标或对话。

## 12. 配置生成 Skill（Configuration Authoring Skill）

配置生成 Skill 是供 AI Agent 使用的设计时工具，不参与世界 Tick 和运行时模拟。

它以世界观设计文档、角色设计文档、统一配置与规则规范及各子系统的领域规范为输入，生成系统运行所需的结构化配置，包括世界事实、初始状态、角色配置、确定性规则及其他子系统要求的配置。

Skill 应识别设计文档中缺失、冲突或无法确定的内容，避免把未经确认的推测直接写入配置。生成结果必须符合统一基础设施支持的格式，并依次通过共享结构验证和对应子系统的领域验证。

该子系统的详细设计将在后续单独进行。完成详细设计时，应同时交付一份可直接供 AI Agent 使用的 Skill；当前阶段只确定其目标和系统位置，不创建 Skill 实现。

## 13. 第一阶段实验范围

保留小型文本虚构世界、一个 AI 角色和一个用户角色。

仅实现少量地点、物品类型与基础身体能力。

优先验证：

1. 角色能够持续感知并执行跨 Tick 行动。
2. 认知能够在身体动作过程中被新事件唤醒。
3. 不同身体行动能够根据资源占用并行或互斥。
4. 用户能够通过自然语言介入角色当前活动。
5. 角色能够形成并维持个人意图与共同决定。
6. 角色能够基于自身感知形成有限、具有主观特征的记忆。
7. 过去经历能够影响后续认知与行动。
8. 角色能够保持沉默或休息，不因 Tick 推进而强制产生新行动。
9. 世界、人物和身体配置能够由同一基础设施完成组合、引用解析、验证及版本识别。
10. 世界规则和身体效果映射能够复用共享的声明式求值、索引和追踪能力，同时保持各自的状态权限。

第一阶段实现可配置的轻量身体状态机制，但暂不实现复杂物理引擎、多角色社会、完整生理模拟、大规模世界生成或复杂人格演化。

## 14. 核心设计原则

**角色不是任务执行器，世界不是预设剧情，记忆不是完美数据库，LLM 也不是世界状态的直接控制者。**

系统应允许角色基于个人历史和有限感知形成意图，通过身体与世界实际交互获得反馈，并在不完整、具有个人特征的记忆基础上持续改变未来行为。

最终目标是让角色拥有独立且连续的生活，使用户能够通过自然交流和共同经历，与其逐渐形成独特的伙伴关系。
